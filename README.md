# 공개 모니터링 상황판

[GitHub Pages 상황판](https://tlzkrh1029.github.io/chatgpt-dot-monitoring-hub/). 운영·게시 대상은 이 저장소와 GitHub Pages입니다. Notion을 읽거나 쓰는 단계는 없습니다.

화면은 열릴 때 data.json과 다섯 범주 파일을 읽고, 60초마다 캐시를 우회해 다시 확인합니다. 탭이 다시 보일 때도 확인하며 전체 페이지를 새로고침하지 않습니다. 범주 필터·포커스·펼친 안내를 유지합니다. 파일별 수신·검증 실패 시 마지막 정상 자료를 표시합니다. 이것은 **게시 파일을 읽는 기능**이며 실제 원문 점검과 요약 작성은 기존 감시 작업이 수행해야 합니다.

## 파일 소유권과 주기

| 감시 작업 | 단독으로 수정할 파일 | 관찰 주기 | 화면의 지연 기준 |
|---|---|---|---|
| 거시·크립토 | data/macro.json | 매시간 | 90분 |
| 미국 중간선거 | data/election.json, data/election-results.json | 매시간 | 90분 |
| 크립토 보안 | data/security.json | 매시간 | 90분 |
| X 계정 연구 | data/xr.json | KST 00/04/08/12/16/19시 | 5시간 |
| 온체인 보안·자금흐름 | data/onchain.json | 매시간 | 90분 |

기준은 public-data.js의 CATEGORY_CONFIG에서 범주별로 설정합니다. 실제 시계와 observedAt을 비교하므로 파일 재수신이나 새 작성 시각만으로 오래된 관찰이 신선해지지 않습니다. 부분 확인·원문 점검 실패·파일 수신 실패도 별도로 표시합니다.

data.json은 기존 공개 기록과 사용자 지정 감시 강도를 보존하는 기본 자료입니다. 감시 작업은 이 파일이나 index.html을 수정하지 않습니다. 각 작업은 자신의 범주 파일만 바꾸므로 동시 실행이 다른 범주를 덮어쓰지 않습니다. 공유 집계 파일 작성 서비스·새 자격 증명은 필요하지 않습니다.

## 범주 JSON 게시 계약 v1

모든 최상위 필드가 필수이고 추가 필드는 거부합니다. 실제 예시는 다섯 범주 파일에 있습니다.

| 필드 | 형식·의미 |
|---|---|
| schemaVersion | 숫자 1 |
| category | macro, election, security, xr, onchain 중 파일명과 같은 값 |
| publishedAt | 공개 JSON 작성·저장 시도 시각. 커밋 성공이나 Pages 배포 완료의 증거가 아님 |
| observedAt | 마지막 실제 원문 점검 시각. 필수·null 불가. 게시 시각으로 대체하지 않음 |
| checkStatus | ok(필요한 점검 완료), partial(일부 범위 미확인), error(이번 원문 점검 실패) |
| headline, body, unknown, gap | 각각 8,000자 이내 일반 텍스트. partial/error이면 gap은 공백이 아닌 내용 필수 |
| feed | 최근 공개 기록 배열, 0–200개. 아래 항목 계약 사용 |

시간은 UTC ISO 8601의 YYYY-MM-DDTHH:mm:ss[.소수]Z 형식으로 소수점 이하 1–9자리를 허용하고 원래 정밀도를 보존합니다. 관찰·피드 시각은 작성 시각보다 나중일 수 없습니다. 현재 시각보다 5분 이상 미래인 값, 관찰 시각의 역행, 다른 범주 소유권은 거부합니다.

피드 항목 필수 필드는 at, kind, title, text입니다. kind는 비어 있지 않은 60자 이내, title과 text는 각각 비어 있지 않은 8,000자 이내 텍스트입니다. 선택 필드는 timeBasis, evidence, sources뿐입니다. evidence는 8,000자 이내 텍스트, sources는 공개 HTTPS URL 0–8개입니다. 항목 내부에 category를 넣지 않습니다.

timeBasis는 생략 시 observation이며 at <= observedAt이어야 합니다. 이미 전달한 알림을 이관할 때는 notification으로 하고 당시 전달 시각을 at에 넣습니다. 화면은 이를 **알림 전달 시각**으로 표시합니다. 이 시각은 새 원문 확인을 뜻하지 않습니다. notification에서도 at <= publishedAt이어야 합니다.

## 공개 범위와 출처

사용자가 승인한 다섯 범주의 공개 요약만 게시합니다. 개인 계정 세부 정보·잔고·비공개 연락처·자격 증명·사적인 원문·Notion 링크를 넣지 않습니다. 내부 메모나 원문 전체를 복사하지 않고 공개 근거와 불확실성을 요약합니다. 감시 강도는 사용자 지정 설정이므로 자동으로 바꾸지 않습니다.

검증기는 최상위·중첩 객체의 미등록 필드, 텍스트 안의 URL/이메일/대표적인 자격 증명 패턴을 거부합니다. URL은 sources에만 넣습니다. 각 URL은 2,048자 이내 HTTPS이며 사용자명·암호·비표준 포트·IP/내부 호스트·계정/설정/로그인 경로·비밀 토큰 쿼리·중첩 URL·프래그먼트를 허용하지 않습니다. Notion, Google Docs/Drive, Slack, ChatGPT, Dropbox, Box, OneDrive 등 사적 문서·작업공간 링크는 차단합니다. X/Twitter는 개별 공개 /사용자/status/숫자 게시물만 허용합니다.

자동 필터는 내용이 공개 가능한지 보증하지 않습니다. 작성 작업은 링크가 실제 공개 근거인지 확인하고 개인 계정 정보가 문장에 섞이지 않도록 정제해야 합니다. 접근 여부를 확인하지 못하면 링크를 빼고 일반적인 확인 한계를 기록합니다.

## 성공·변화 없음·실패 처리

1. 자신의 범주 파일을 최신 SHA와 함께 읽고 기존 공개 기록을 보존합니다.
2. 새 원문을 실제 점검한 경우에만 observedAt을 진행시킵니다. 변화가 없어도 실제 점검했다면 그 시각과 확인 범위를 기록할 수 있습니다.
3. 원문 점검 전체 실패 시 이전 observedAt·제목·본문·피드를 유지합니다. checkStatus를 error로 하고 gap에 공개 가능한 일반적인 실패 사유를 기록합니다. 오류만으로 새 피드 사실을 만들지 않습니다. 부분 확인은 확인한 범위와 미확인 범위를 구분합니다.
4. 기존 기록과 새 기록을 중복 제거해 합치고 최신 200개를 보존합니다. 수정·정정은 기존 항목을 지우지 말고 별도 기록합니다. data.json의 기존 역사 기록은 항상 함께 표시됩니다. 범주 파일의 오래된 기록도 Git 커밋 이력에 남습니다.
5. publishedAt을 공개 JSON 준비 시각으로 작성하고 검증합니다. 자신의 파일만 현재 SHA를 조건으로 갱신합니다. 충돌하면 같은 파일을 다시 읽고 다시 합칩니다. 강제 덮어쓰기나 다른 범주의 집계는 하지 않습니다.
6. 쓰기 성공 후 정확한 원격 커밋/파일을 다시 읽어 저장을 확인합니다. Pages 배포와 실제 사이트 파일 확인은 별도 단계입니다. 성공을 확인하기 전에는 저장·배포가 끝났다고 보고하지 않습니다.

화면은 마지막 정상 자료를 현재 탭의 메모리에 유지합니다. 새 탭에서는 저장소의 기본 자료가 대체 자료입니다. 폴링 요청은 한 번에 하나만 실행하고 각 요청은 15초로 제한합니다. 범주 하나의 실패는 다른 범주의 갱신을 중단하지 않습니다. 원문 점검 시각, 공개 JSON 작성 시각, 브라우저 정상 수신 시각은 구분합니다.

## 점검과 배포

Node.js 18 이상이면 추가 패키지 설치 없이 실행합니다.

~~~sh
npm test
npm run validate
~~~

브라우저와 로컬 검증은 같은 public-data.js 계약을 사용합니다. 테스트는 성공 재수신, 시계 기반 지연, 통신/파싱/스키마 오류, 마지막 정상 자료 보존, 범주 격리, 시각 역행, 요청 중첩·시간 제한, 공개 URL 제한과 역사·설정 보존을 확인합니다.

기존 main 브랜치 기반 GitHub Pages 배포를 사용합니다. 코드와 초기 자료를 한 커밋으로 게시하고 원격 SHA 및 실제 Pages 결과를 확인합니다. 이후 각 감시 파일 갱신으로 기존 Pages 배포가 수행됩니다. GitHub 배포·캐시 지연은 브라우저 폴링과 별개입니다. 병렬 타임라인 탭을 빼면 별도 예약 GitHub Actions, 외부 서비스, 새 비밀값은 추가하지 않습니다. 병렬 타임라인 탭은 전용 예약 워크플로(`.github/workflows/update-parallel-prices.yml`)로 Yahoo Finance와 Coin Metrics에서 시세를 수집하며, 이 작업도 새 비밀값 없이 기본 `GITHUB_TOKEN`만 씁니다(아래 "병렬 타임라인 탭" 참고).

?view=status, ?view=feed, ?view=checks는 선택적으로 한 영역만 보는 화면입니다. 기본 주소는 전체 상황판입니다.

## 화면의 네 범주

화면은 거시·크립토, 미국 중간선거, 크립토 보안·해킹, X 계정 연구의 네 범주를 표시합니다. 보안 타일 안에는 사건·복구와 ZachXBT 조사·자금 추적이 있으며 각자의 관찰 시각, 작성 시각, 부분 확인·수신 실패 상태와 자료 한계를 그대로 표시합니다.

이 통합은 display-data.js의 화면 매핑에만 적용합니다. 다섯 CATEGORY_CONFIG 키, 수집 작업, JSON 파일, 일정, 검증 계약과 새로고침 요청은 독립적으로 유지합니다. 보안 필터는 security와 onchain의 원본 기록을 모두 포함하며, 건수는 사건 수가 아니라 원본 기록 수입니다.

보안 피드는 단일 대상이 명확한 Binance, GitBook, Mercado Bitcoin, BTCPay, Chainalysis 기록을 대상별 관련 이력으로 접어 표시합니다. 같은 대상의 여러 사고를 하나의 사고로 확정하는 기능이 아닙니다. 여러 대상을 함께 다룬 종합 기록과 대상이 불명확한 기록은 별도로 남깁니다. 관련 이력을 펼치면 각 기록의 원문·정정·시각·근거·출처를 모두 볼 수 있습니다. 금액을 합산하거나 데이터를 삭제하지 않습니다. 펼침 상태와 포커스는 새 자료 수신 후에도 유지합니다.

## 병렬 타임라인 탭

`parallel.html`은 기존 상황판과 분리된 시장 병렬 타임라인입니다. 주식지수, AI·반도체 종목, 크립토, 달러·금의 네 패널이 한 날짜의 08:00–16:00 KST를 같은 15분 시간축으로 보여 줍니다. 분석 노트가 있는 날은 사건선과 함께 한 줄, 세부, 읽기, 볼 것, 스토리텔링, 판정을 표시합니다.

시세는 이 탭 전용 예약 Actions 작업(`update-parallel-prices.yml`)이 평일 08:07–16:52 KST에 15분마다 수집합니다. 장중 자료는 자료 전용 브랜치 `parallel-data`에만 올리고, 마감이 확정된 세션만 main의 `data/parallel/`에 보관하므로, 장중 수집이 main의 커밋과 Pages 빌드를 늘리지 않습니다. 화면은 `parallel-data`의 자료를 raw.githubusercontent.com에서 먼저 읽습니다. 출처는 Yahoo Finance(개인 비상업 열람용)와 Coin Metrics Community(CC BY-NC 4.0)입니다. 분석 노트는 main의 `data/parallel/notes/YYYY-MM-DD.json`에 따로 씁니다. 기존 다섯 범주의 파일·계약·감시 주기는 바꾸지 않으며, 새 비밀값도 필요하지 않습니다.

이 워크플로는 이 탭의 테스트(`tests/parallel-*.test.js`)와 `scripts/validate-parallel.js`만으로 게시 여부를 정하므로, 다른 탭의 자료나 테스트는 시세 게시를 막지 않고 분석 노트의 오류는 경고로만 남습니다. `npm test`와 `npm run validate`도 이 탭의 코드와 자료를 함께 점검합니다. 자료 형식, 수집 일정과 실패 처리, 노트 작성법, 수동 실행, 로컬 미리보기는 [docs/parallel-timeline.md](docs/parallel-timeline.md)에 있습니다.

## 선거 결과 탭

`election-results.html`은 기존 상황판과 분리된 미국 중간선거 결과 화면입니다. 상원·하원 반원 의석도, 50개 주를 같은 크기 칸으로 놓은 타일 지도(상원·주지사 전환), 남은 미판정 경합의 격차 점 그래프와 목록을 보여 줍니다. 판정된 경합만 정당 색으로 칠하고, 앞선 후보는 승자로 표시하지 않습니다.

전용 게시 파일은 `data/election-results.json`, 계약은 `election-results-data.js`, 화면은 `election-results-view.js`와 `election-results.css`입니다. 기존 다섯 범주 계약과 병렬 탭 계약은 바꾸지 않습니다. 미국 중간선거 감시 작업이 `data/election.json`과 같은 회차에 이 파일을 갱신하며, 판정 기준·필드·갱신 절차는 [docs/election-results-data.md](docs/election-results-data.md)에 있습니다. `npm test`와 `npm run validate`가 새 계약도 함께 점검합니다.

`?view=power`, `?view=map`, `?view=close`는 노션에 나눠 임베드할 때 쓰는 보기입니다. 기본 주소는 전체 화면입니다.
