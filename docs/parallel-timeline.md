# 병렬 타임라인 탭 운영 안내

`parallel.html`은 기존 상황판과 분리된 시장 병렬 타임라인입니다. 화면은 한 KST 날짜의 08:00–16:00을 15분 격자로 나누고, 주식지수, AI·반도체 종목, 크립토, 달러·금의 네 패널이 이 시간축을 함께 씁니다. 시세는 GitHub Actions의 수집기가 모읍니다. 장중 자료는 자료 전용 브랜치 `parallel-data`에만 올리고, 마감이 확정된 세션만 main의 `data/parallel/`에 보관합니다. 사건선과 해설은 분석가가 main에 날짜별 노트 파일로 씁니다. 화면은 이 파일들을 읽기만 합니다.

## 화면 구성

### 네 패널

| 패널 | 기준 | 계열(원자료 기호) |
|---|---|---|
| 주식지수 | 전일 종가 대비 % | 코스피 `^KS11`, 니케이225 `^N225`, 대만 가권 `^TWII`, 항셍 `^HSI`, 나스닥100 선물 `NQ=F`(08:00 KST 대비) |
| AI·반도체 종목 | 전일 종가 대비 % | SK하이닉스 `000660.KS`, 삼성전자 `005930.KS`, TSMC `2330.TW`, 소프트뱅크 `9984.T`, 어드반테스트 `6857.T` |
| 크립토 | 08:00 KST 대비 % | BTC, ETH, HYPE, ZEC, XMR: Coin Metrics 우선, 실패하면 Yahoo `BTC-USD`, `ETH-USD`, `HYPE32196-USD`, `ZEC-USD`, `XMR-USD` |
| 달러·금 | 08:00 KST 대비 % | 달러지수 `DX-Y.NYB`, 달러/원 `KRW=X`, 달러/엔 `JPY=X`, 금 선물 `GC=F` |

- 전일 종가는 거래소 현지 날짜로 본 직전 거래일의 종가입니다. 전날이 휴장이었던 시장은 그보다 앞선 거래일의 종가가 기준이 되며, 차트 설명에 "11/2 종가 기준: 니케이225·소프트뱅크·어드반테스트"처럼 따로 적습니다. Yahoo 일봉에 있는 휴장일 자리표시 봉(시가·고가·저가·종가가 모두 같고 거래량이 0인 봉)은 건너뛰므로, 기준 이름에는 실제로 거래한 날짜가 들어갑니다. 일봉 요청이 실패하면 15분봉 응답에 든 전일 종가를 쓰고 기준 이름을 `전일 종가`로 둡니다. 둘 다 없으면 그 계열은 받은 점을 쓰지 않습니다(아래 "실패할 때").
- 08:00 KST 대비 계열은 08:00 KST의 값을 기준으로 씁니다. 그 값이 없으면 08:00 봉의 시가를 쓰고, 그것도 없으면 시각과 관계없이 구간 안의 첫 관측값을 씁니다. 예를 들어 11/2(월)의 달러/원과 달러/엔은 09:00에, 미국 서머타임이 끝나기 전인 10/27~10/30의 달러지수는 08:45에 첫 값이 들어왔습니다. 기준 이름(`08:00 KST`, `08:00 KST 시가`, `첫 관측 09:00 KST`)에 어느 값을 썼는지 남기며, 첫 값이 늦다는 이유로 받은 관측값을 버리지 않습니다. Coin Metrics 계열도 08:00 KST 값이 없으면 구간 안의 첫 값을 기준으로 씁니다.
- 수집기는 공식 종가를 공식 마감 시각(코스피·니케이 15:30, 대만 14:30)에 찍습니다. 종가가 담긴 봉이 그 시각보다 늦게 시작하면 봉의 시각에 그대로 두고, 종가를 앞당기지는 않습니다. 아직 끝나지 않은 15분봉은 마지막 시세 시각의 실시간 값으로 찍습니다.
- 점심 휴장이 있는 시장은 오전 마감 값을 휴장이 시작하는 시각에 찍고, 휴장 안에는 점을 두지 않습니다. 니케이225·소프트뱅크·어드반테스트는 11:30, 항셍 13:00(현지 12:00)입니다. 이 시각은 `parallel-core.js`의 계열 목록 `SERIES`에 계열마다 `closeKst`(공식 종가 시각)와 `breakKst`(점심 휴장 직전 오전 마감 봉이 시작하는 KST 시각, 해당 없으면 `null`)로 들어 있습니다.
- 차트는 관측 간격이 15분보다 길고 125분 이하이면 흐린 점선으로 잇고, 125분보다 길면 잇지 않습니다. 점심 휴장도 이렇게 흐린 점선으로 이어집니다. 빈 구간을 다른 값으로 채우지 않습니다.
- 패널의 세로축은 늘 0을 포함하며, 움직임이 작은 아침에 잡음이 크게 보이지 않도록 적어도 ±0.5%(달러·금은 ±0.2%)를 보여 줍니다. 오른쪽 끝 이름표는 계열 색 표시와 마지막 값을 세로축 눈금에 맞는 자릿수로 보여 줍니다(폭이 640px보다 좁으면 이름표 대신 범례에 마지막 값을 붙입니다). 선이 오른쪽 끝보다 일찍 끝나면(일찍 마감한 시장, 수집 중인 날짜, 지연된 계열) 흐린 점선이 선 끝에서 이름표까지 이어집니다.

### 사건선

노트의 `events`는 모든 패널을 가로지르는 세로 점선으로 그려지고, 첫 패널 위에 이름 두 줄(`label`, `sub`)이 붙습니다. `end`가 있는 사건은 시작부터 끝까지 파란 띠로 그립니다. 라벨을 세 줄 안에 겹치지 않게 놓을 수 없거나 화면 폭이 640px보다 좁으면, 차트는 이름 대신 ①② 같은 번호를 표시하고 그 아래에 번호별 이름 목록을 함께 그립니다. 번호마다 이름과 시각을 담은 제목이 있어 포인터를 올리면 보이며, 이 번호는 사건 목록의 번호와 같습니다.

### 화면 순서

| 순서 | 영역 | 채우는 곳 |
|---|---|---|
| 1 | 머리글: 제목, 날짜와 구간, 부제, 날짜 선택, 상태, 테마, PNG 저장 | `notes.title`, `notes.subtitle`, 세션 |
| 2 | 한 줄 | `notes.headline` |
| 3 | 차트 | 세션 시세, `notes.events` |
| 4 | 차트에서 바로 보이는 것 | `notes.observations`, 이어서 기준 시각 줄과 "자동" 항목 |
| 5 | 시간표(패널 선택, % / 가격 전환) | 세션에서 자동 계산: 정시별 값, 최저(강조), 마지막 |
| 6 | 세부·읽기 카드 | `notes.sections` |
| 7 | 볼 것 | `notes.watch` |
| 8 | 스토리텔링 | `notes.story`(단락마다 출처 줄) |
| 9 | 판정 | `notes.verdict` |
| 10 | 사건 목록 | `notes.events`(다른 출처의 시각 포함) |
| 11 | 바닥글 | 출처와 라이선스, 작성자와 기준 시각, `notes.footnote`, 계열별 기준과 상태 |

노트가 없는 날은 차트, 자동 항목, 시간표만 보이고 "이 날짜의 분석 노트가 없습니다."라는 안내가 한 번 나옵니다. 노트를 받지 못한 경우의 안내는 아래 "실패할 때"에 있습니다.

### 자동 항목

"자동" 항목은 세션 자료로 계산한 사실만 적고 인과를 주장하지 않습니다. 최대 7개이며, 계산에 쓸 자료가 모자란 항목은 빠집니다. `stale`·`error` 계열(아래 "실패할 때")은 모든 항목에서 뺍니다. 그래서 "바닥 시각: 11/17개 계열"처럼 세는 수에도 들어가지 않습니다.

| 항목 | 내용 |
|---|---|
| 바닥 시각 | 0.5% 이상 내린 계열이 3개 이상일 때, 그 최저점의 60% 이상이 모인 가장 짧은 구간과 그 앞뒤 15분 안의 사건 |
| 가장 가파른 동반 반등 | 5개 이상 계열의 30분 변화 평균이 가장 큰 구간. 평균이 반올림해 +0.1p 이상일 때만 나옴 |
| 낙폭 회복 | 1% 이상 내린 계열을 둘로 나눕니다. "낙폭 전부 회복(기준선 위)"은 기준선 위로 돌아온 계열을 마지막 값 순으로 3개까지 적고 나머지는 "외 n개"로 셉니다. "회복률(기준선 아래)"은 아직 기준선 아래인 계열의 회복 비율을 상위와 하위 3개씩 적습니다. 기준선 아래 계열은 99%를 넘겨 적지 않고, 상위와 하위가 같은 정수로 반올림되면 회복률 부분을 생략합니다 |
| 가장 깊은 낙폭 | 최저점이 가장 낮은 3개 계열과 그 시각 |
| 기준선 아래로 거의 내려가지 않은 계열 | 최저가 −0.6% 이상이고 마지막 값이 +0.5% 이상인 계열 |
| 후행 움직임 | 60분 변화가 가장 큰 구간이 1.0p 이상이고, 그 구간이 동반 반등이 끝난 뒤에 시작한 계열. 반등 항목이 없거나 반등이 바닥 구간보다 먼저 끝났으면 바닥 구간 끝 + 45분부터 셉니다. 늦게 시작한 움직임부터 3개까지 시각 순으로 적고, 바닥 시각 항목이 있을 때만 나오며, 끝에 "(다른 자산 반등 이후 움직임)"이 붙습니다 |
| 마지막 값 상위·하위 | 마지막 값 기준 상위와 하위 3개씩 |

자동 항목 바로 위에는 기준 시각 줄이 흐린 글씨로 붙습니다. 11/4의 예는 "자동 항목은 차트 끝 기준(장 마감 계열은 종가). 분석 노트는 15:00 기준"입니다.

- 괄호 안의 "장 마감 계열은 종가"는 표시한 계열 중 하나라도 종가에서 끝났을 때만 나옵니다.
- 자동 항목에서 뺀 지연 계열이 있으면 "지연된 코스피 제외"처럼 이름을 적고, 4개 이상이면 "지연된 n개 계열 제외"로 셉니다.
- "분석 노트는 HH:MM 기준"은 노트의 `asOf`가 표시 구간 끝보다 이를 때만 붙고, `asOf`가 다른 날짜이면 앞에 "M/D"를 붙입니다. 자동 항목과 노트의 수치가 다르게 보이면 대개 이 기준 시각의 차이 때문입니다.

### 도구와 갱신

- 날짜 선택은 수집된 날짜를 최신순으로 보여 줍니다. 주소에 `?date=YYYY-MM-DD`를 붙이면 그 날짜를 엽니다.
- 주소에 날짜가 없으면 가장 최근 날짜를 엽니다. 다만 그 날짜가 아직 수집 중(최종 아님)이고 자료가 있는 계열이 10개 미만이거나 자료가 30분 치가 안 되면, 그보다 앞선 최종 날짜가 있을 때 그 날짜를 열고 본문 맨 위에 "오늘(M/D) 세션 수집 중 · 보기"를 띄웁니다. "보기"를 누르면 수집 중인 날짜로 바뀝니다. 수집 중인 날짜가 오늘이 아니면 이 문구는 "M/D(요일) 세션 자료 적음 · 보기"입니다.
- 고른 날짜를 받지 못하면 날짜 선택과 주소가 보던 날짜로 돌아가고, 도구 줄에 "M/D(요일) 자료를 불러오지 못했습니다: 사유"가 잠시 나옵니다. 같은 날짜를 다시 고르면 다시 시도합니다.
- 상태 표시는 다음 중 하나입니다. 상태에 포인터를 올리면 해당 계열이 "이전 자료 표시: 코스피(09:45까지) · 수집 실패: 항셍"처럼 나옵니다.

| 상태 | 뜻 |
|---|---|
| "실시간 · HH:MM 갱신" | 수집 중인 날짜. HH:MM은 세션 파일을 만든 시각 |
| "갱신 지연 · M/D HH:MM" | 수집 중인 날짜인데 파일을 만든 지 30분이 넘었거나 구간 끝에서 1시간이 지남 |
| "최종" | 확정된 날짜 |
| " · 일부 지연 n", "최종 · 일부 수집 실패 n" | `stale`·`error` 계열이 n개 있음. " · 일부 지연 n"은 앞의 두 상태 뒤에 붙고, "최종 · 일부 수집 실패 n"은 "최종"을 대신함 |
| "수신 실패 · 마지막 정상 자료" | 받기나 검증에 실패해 직전 자료를 유지. 처음부터 받지 못했으면 "수신 실패" |

- 차트에 포인터를 올리거나 누르면 그 시각의 모든 값(등락률과 가격)이 나옵니다. 휴대폰에서는 차트를 누른 채 옆으로 끌어 시각을 옮기고, 두 손가락으로 확대할 수 있습니다.
- Tab 키로 차트에 초점을 두면 ← → 키나 ↑ ↓ 키로 15분씩, Home·End 키로 처음과 끝으로 시각을 옮기고 Esc 키로 닫습니다. 이 조작은 차트 안의 시각 슬라이더가 받으므로 화면 낭독기에서도 쓸 수 있으며, 슬라이더는 "12:15 KST"처럼 시각을 알려 주고 그 시각의 모든 값을 이어서 읽어 줍니다.
- 시간표는 패널 단추로 패널을 고르고, "%"와 "가격" 단추로 등락률과 가격(지수 포인트, 현지 통화 주가, USD 가격 등)을 바꿉니다. 다른 쪽 숫자는 칸에 포인터를 올리면 보입니다. 수집 중인 날짜는 마지막 자료 이후의 정시 줄을 빼고 시간표 위 줄에 "HH:MM까지"를 붙이므로, 표 안의 "·" 칸은 실제로 빠진 값입니다. `stale` 계열의 열 머리에는 "09:45까지"처럼 자료가 끝난 시각이, `error` 계열에는 "수집 실패"가 붙습니다.
- 기본 테마는 어두운 화면이고 "밝은 화면" 버튼으로 바꿉니다. 이 선택은 그 브라우저에만 저장됩니다.
- "PNG 저장"은 머리글과 아래 줄을 넣은 밝은 그림(폭 1400px, 2배 해상도)을 내려받고, "어두운 PNG"는 같은 그림을 어두운 테마로 내려받습니다.
  - 머리글에는 제목, 구간, 부제가 들어갑니다. 수집 중인 날짜는 구간이 마지막 자료 시각에서 끝나고 "(11/4 08:00~11:00 KST · 11:03 현재)"처럼 내려받은 시각이 붙으며, 화면의 차트에도 현재 시각 선에 "HH:MM 현재"가 붙습니다.
  - 아래 줄은 노트 작성자, 이어서 화면의 차트 설명(기준, 기준 예외, 출처, 지연·실패 계열, 자료 생성 시각)입니다.
  - 파일 이름은 `parallel-timeline-YYYYMMDD.png`와 `parallel-timeline-YYYYMMDD-dark.png`이고, 수집 중인 날짜는 세션 파일을 만든 KST 시각을 붙여 `parallel-timeline-YYYYMMDD-HHMM.png`가 됩니다.
- 선택한 날짜가 최종이 아니면 화면은 탭이 보이는 동안 5분마다, 그리고 탭으로 돌아올 때 index, 세션, 노트를 다시 읽습니다. 구간 끝에서 24시간이 지나면 다시 읽기를 멈춥니다. 최종 날짜는 다시 읽지 않습니다.
- 읽기에 실패하면 최종 날짜도 30초, 2분, 5분 뒤에 다시 시도하고, 그 뒤로는 5분마다 시도합니다. 실패한 상태에서 탭으로 돌아와도 다시 읽습니다. 다시 읽은 내용이 같은 영역은 새로 그리지 않으므로 키보드 초점이 그대로 남습니다.
- 화면을 github.io에서 열면 raw.githubusercontent.com의 사본을 먼저 읽습니다. index와 세션은 `parallel-data` 브랜치, main 브랜치, 같은 사이트의 `data/parallel/` 순서로 읽고, 노트는 main에서 쓰므로 main, `parallel-data`, 같은 사이트 순서로 읽습니다. 뒤에 다른 주소가 남은 요청은 5초, 마지막 주소는 15초까지 기다리며, 연결 오류나 시간 초과가 난 호스트는 10분 동안 맨 뒤로 미룹니다. 그래서 장중 자료는 Pages 빌드를 기다리지 않고 몇 분 안에 보입니다. 다른 주소에서는 같은 사이트의 파일만 읽습니다.

## 자료 위치와 형식

~~~
main 브랜치의 data/parallel/
  index.json                 main에 있는 세션의 목록
  sessions/YYYY-MM-DD.json   최종 세션의 보관본(수집 작업이 복사)
  notes/YYYY-MM-DD.json      분석가 작성: 사건과 해설(선택)
parallel-data 브랜치의 data/parallel/
  index.json                 모든 세션의 목록
  sessions/YYYY-MM-DD.json   수집 중인 세션과 지난 세션(수집 작업이 회차마다 갱신)
  notes/                     main의 notes/를 그대로 옮긴 사본
~~~

- `parallel-data`는 `data/parallel/`만 담는 브랜치이며, main과 이력이 이어지지 않습니다(orphan). 첫 게시 때 만들어집니다.
- main이 아닌 브랜치에서 수동 실행한 결과는 `parallel-data-<브랜치 이름>`에 쌓입니다. 브랜치 이름에서 영문·숫자·`.`·`_`·`-`가 아닌 글자는 한 글자마다 `-`로 바꿉니다(예: `claude/test`는 `parallel-data-claude-test`). 화면은 `parallel-data`만 읽습니다.
- 수집 작업은 data 브랜치의 세션 파일을 지우지 않습니다. 세션을 없애려면 main과 data 브랜치에서 모두 지워야 하며, 한쪽에만 남아 있으면 다음 회차가 그 파일을 다시 옮깁니다. 노트는 main이 원본이므로 main에서 지우면 data 브랜치의 사본도 다음 회차에 지워집니다.
- 세 파일 모두 UTF-8 JSON이고 `schemaVersion`은 3입니다. `kind`는 각각 `index`, `session`, `notes`입니다.
- 시각은 모두 `Z`로 끝나는 UTC ISO 문자열입니다(예: `2026-11-04T00:15:00Z`). 날짜는 KST 달력 날짜이고, KST는 서머타임이 없는 UTC+9입니다.
- 읽는 쪽은 모르는 필드를 무시합니다. 그래도 쓰는 쪽은 이 문서에 없는 필드를 만들지 않습니다.
- 검증 규칙은 `parallel-core.js`의 `validateIndex`, `validateSession`, `validateNotes`에 있습니다. 화면도 같은 함수로 파일을 검사합니다.

### index.json

최상위의 `updatedAt`과 `sessions` 배열로 이루어지며, `sessions`에는 날짜가 최신순으로 들어갑니다. 각 항목은 `date`, `title`(노트 제목, 노트가 없으면 `null`), `final`, `seriesWithData`(점이 있는 계열 수), `updatedAt`(그 세션의 `generatedAt`), `hasNotes`를 가집니다. 수집 작업은 브랜치마다 그 브랜치에 있는 세션과 노트로 목록을 다시 만들며(`--rebuild-index`), 이때 최상위 `updatedAt`은 그중 가장 최근 세션의 `generatedAt`입니다.

### 세션 파일

| 필드 | 뜻 |
|---|---|
| `date`, `timezone` | KST 날짜, `"Asia/Seoul"` |
| `window` | 수집 구간 `{start, end}`. 기본 08:00–16:00 KST는 전날 `23:00:00Z`부터 당일 `07:00:00Z`까지 |
| `intervalMinutes` | `15` |
| `generatedAt` | 이 파일을 만든 시각. 받은 시각 말고는 바뀐 것이 없는 회차는 파일을 쓰지 않으므로 이 값도 그대로 남음 |
| `final` | 구간 끝 + 20분 이후에 만든 파일이면 `true` |
| `series` | 계열 19개. 아래 표 |
| `providers` | 출처 표기: Yahoo Finance, Coin Metrics Community(라이선스 포함) |

| 계열 필드 | 뜻 |
|---|---|
| `id`, `panel`, `label` | 계열 식별자, 패널(`indices`, `ai`, `crypto`, `fx`), 화면 이름 |
| `basis` | `prevClose`(전일 종가 대비) 또는 `windowStart`(08:00 KST 대비) |
| `baseline` | `{value, label}`. label 예: `11/3 종가`, `전일 종가`, `08:00 KST`, `08:00 KST 시가`, `첫 관측 09:00 KST`. value는 `missing`·`error`일 때만 `null`일 수 있음 |
| `source` | 실제로 쓴 원자료 `{provider, symbol}`. 이전 점만 그대로 남긴 계열은 그 점의 출처 |
| `status`, `note` | 상태와 사유. 아래 "실패할 때" 참고 |
| `fetchedAt` | 이 계열을 마지막으로 받은 시각. 이전 점만 그대로 남긴 계열은 그 점을 받은 시각 |
| `points` | `[시각, 값, 등락률]`의 배열. 시각 오름차순, 구간 안, 값은 0보다 큼. 등락률(%)은 100 × (값 ÷ 기준값 − 1)을 소수 셋째 자리까지 반올림한 값 |

## 수집기

`scripts/collect-parallel.js`는 한 번 실행될 때 한 날짜의 세션 파일을 만들거나 갱신하고 `index.json`을 다시 맞춥니다. 모든 옵션은 `node scripts/collect-parallel.js --help`로 볼 수 있습니다.

- 날짜(`--date`)를 주지 않으면 현재 세션을 수집하며, 그날 구간 시작(기본 08:00 KST) 전에는 전날 세션을 갱신합니다. 오늘(KST)보다 늦은 날짜를 주면 아무것도 하지 않고 종료 코드 2로 끝나며, 구간이 아직 시작하지 않은 세션은 쓰지 않습니다.
- 구간(`--start`, `--end`)을 주지 않으면 기존 파일의 구간을 그대로 씁니다. 기존 파일과 다른 구간을 주면 요청 없이 종료 코드 2로 끝나고, `--replace-window`를 함께 주면 저장된 점을 버리고 새 구간으로 다시 만듭니다.
- 같은 날짜, 같은 구간의 기존 파일이 있으면 전일 종가 기준값을 재사용하고, 새 응답과 저장된 점을 합칩니다(아래 "실패할 때").
- 결과가 받은 시각(`generatedAt`, `fetchedAt`) 말고는 기존 파일과 같으면 파일을 쓰지 않습니다(`unchanged`).
- 날짜를 주지 않은 실행은 구간 끝 + 20분이 지났는데도 최종이 아닌 이전 세션을 최근 것부터 5개까지 한 번씩 더 수집해 마감합니다. 주말이라 현재 세션을 건너뛰는 회차도 이 일은 합니다. Yahoo 요청이 멈췄거나 한 회차의 6분 수집 시간이 2분도 남지 않았으면 다음 회차로 미루며, 수집 도중 Yahoo 요청이 멈춘 세션은 쓰지 않습니다.
- `--overlay-dir 폴더`를 주면 수집하기 전에, 그 폴더의 `sessions/`에서 검증을 통과하고 `--data-dir`의 사본보다 `generatedAt`이 늦은(또는 사본이 없는) 세션 파일을 그대로 복사해 씁니다. 워크플로는 data 브랜치의 세션을 이렇게 넘깁니다. 노트는 이 폴더에서 읽지 않습니다.
- `--rebuild-index`는 요청 없이 `--data-dir`의 세션과 노트로 `index.json`만 다시 만들고 끝납니다. 내용이 같으면 파일을 쓰지 않습니다.
- `--dry-run`은 받아서 요약만 출력하고 파일은 쓰지 않습니다. `--fixtures 폴더`는 제공자 응답을 파일(`<기호>.intraday.json`, `<기호>.daily.json`, `coinmetrics.json`)에서 읽고(기호의 영문·숫자·`.`·`-` 밖의 글자는 `_`로 바꿈, 예: `_KS11.intraday.json`), `--now`는 현재 시각을 바꿔 시험할 때 씁니다.
- 종료 코드는 정상(쓰기, 변화 없음, 건너뜀, `--dry-run`)이면 0, 사용법 오류면 2, 그 밖의 실패면 1입니다. Actions에서는 `GITHUB_OUTPUT`에 `date`, `final`, `status`(`written`, `unchanged`, `skipped`, `dry-run`), `written`(이번에 쓴 세션 날짜들)을 남깁니다.

### 실행 시각

| 계기 | 시각(KST, 평일) | 목적 |
|---|---|---|
| 예약 | 08:07–16:52, 15분마다(:07 :22 :37 :52) | 장중 수집 |
| 예약 | 17:17, 19:17, 22:17 | 마감 확정과 누락 보충 |
| main push: `data/*.json` | 다른 감시 작업이 범주 파일을 올릴 때 | 예약 실행이 밀리거나 빠질 때의 보조 신호 |
| main push: `data/parallel/notes/**` | 분석 노트를 올릴 때 | 날짜 목록의 노트 제목과 data 브랜치의 노트 사본 갱신 |
| main push: 워크플로, `scripts/collect-parallel.js`, `parallel-core.js` | 코드가 바뀔 때 | 새 코드로 한 번 실행 |
| 수동 실행 | 언제든 | 아래 "수동 실행" 참고 |

- 예약 실행과 push 실행은 원래 저장소(`tlzkrh1029/chatgpt-dot-monitoring-hub`)의 main에서만 돕니다. 포크에서는 수동 실행으로만 수집합니다.
- GitHub의 예약 실행은 부하에 따라 늦어지거나 빠질 수 있습니다. 그래서 예약 시각을 정각에서 7분 늦추고(:07 :22 :37 :52), 매시간 범주 파일을 올리는 다른 감시 작업의 push를 보조 신호로 씁니다.
- push는 기본 `GITHUB_TOKEN`으로 하므로, 이 작업의 push가 이 작업을 다시 시작하지 않습니다.
- 수집기는 다음 경우에 시세를 요청하지 않고 정상 종료합니다. 건너뛴 이유는 실행 기록에 남습니다.
  - push로 시작한 회차(`--throttle`)에서 기존 파일을 만든 지 10분이 지나지 않았을 때(`throttled`). 예약 실행과 수동 실행에는 이 제한이 없습니다.
  - 기존 파일이 이미 최종이고(구간 끝 + 20분 이후에 만듦) `stale`·`error` 계열이 없을 때(`final`)
  - 기존 파일이 최종이지만 `stale`·`error` 계열이 있고, 만든 지 60분이 지나지 않았을 때(`repair-wait`)
  - 기존 파일이 최종이고 `stale`·`error` 계열이 있지만, 구간 끝에서 8시간(기본 24:00 KST)이 지났을 때(`repair-closed`). 계속 실패하는 계열 때문에 밤새 요청을 반복하지 않도록 자동 복구를 멈추고, 그 계열은 `stale`·`error` 상태로 남깁니다.
  - 날짜를 주지 않았고 현재 세션 날짜가 KST로 토요일이나 일요일일 때(`weekend`). `--date`를 주면 주말 날짜도 수집합니다.
  - 세션 구간이 아직 시작하지 않았을 때(`not-started`)
- `--force`를 주면 `throttled`, `final`, `repair-wait`, `repair-closed` 조건과 관계없이 수집합니다.
- 건너뛰는 회차도 노트 파일을 읽어 `index.json`의 제목과 `hasNotes`를 맞춥니다. 내용이 바뀌었을 때만 파일을 씁니다.
- 구간 끝 + 20분(기본 16:20 KST) 이후에 만든 파일은 `final: true`가 됩니다. 보통 16:22 회차가 최종 파일을 만들고, 17:17·19:17·22:17 회차는 앞 회차가 빠졌을 때 마감하거나 `stale`·`error`가 남은 최종 파일을 다시 수집합니다. 최종 파일은 만든 지 60분이 지나야 다시 수집하므로, 16:22에 만든 파일이면 17:17 회차는 건너뛰고 19:17 회차가 다시 수집합니다. 다시 수집한 결과가 받은 시각 말고는 같으면 파일을 쓰지 않으므로, 실패가 이어지는 동안에는 그 뒤의 회차마다 다시 요청합니다. 이 자동 복구는 구간 끝에서 8시간이 지나면 멈춥니다(`repair-closed`). 그 뒤에 복구하려면 수동 실행에서 `force`를 켭니다.

### 한 회차의 순서

1. 실행한 브랜치를 모든 브랜치의 이력과 함께 받고(data 브랜치 포함), 인증 정보는 작업 폴더의 git 설정에 남기지 않습니다. Node 22를 준비합니다.
2. `node --test tests/parallel-*.test.js`로 이 탭의 테스트만 실행합니다. 저장소의 실제 자료 파일을 읽는 테스트는 `PARALLEL_SKIP_LIVE_DATA_TESTS=1`로 건너뜁니다(그 파일은 5단계에서 검사합니다). 테스트가 실패하면 제공자에 요청하기 전에 멈춥니다.
3. data 브랜치의 `data/parallel/sessions`를 임시 폴더로 꺼냅니다. 브랜치가 아직 없으면 꺼낼 것 없이 넘어갑니다.
4. `node scripts/collect-parallel.js`를 실행합니다. 3단계의 폴더를 `--overlay-dir`로 넘기고, push로 시작한 회차는 `--throttle`을 붙입니다. 수동 실행은 입력값을 `--date`, `--start`, `--end`, `--force`, `--replace-window`로 넘깁니다. 종료 코드가 0이 아니면(미래 날짜, 맞지 않는 구간 등) 여기서 실패로 끝납니다.
5. `node scripts/validate-parallel.js --notes=warn`으로 수집한 자료를 검사합니다. index와 세션의 오류는 실패로 끝내고, 노트의 오류는 `parallel notes` 경고로만 남깁니다.
6. data 브랜치에 게시합니다. 시도마다 그 브랜치의 최신 커밋에서 다시 시작합니다. 검증을 통과하고, 브랜치에 사본이 없거나 사본보다 `generatedAt`이 늦은 세션만 복사하고, `notes/`를 실행한 브랜치의 `notes/`와 똑같이 맞추고, `--rebuild-index`로 목록을 다시 만들어 다시 검사합니다. 바뀐 것이 있을 때만 `Update parallel timeline data (YYYY-MM-DD HH:MM KST)`로 커밋해 push합니다. 브랜치가 없으면 이때 새로 만듭니다.
7. 실행한 브랜치(보통 main)에 최종 세션을 보관합니다. 그 브랜치의 최신 커밋으로 작업 폴더를 새로 만들어, 최종 세션 가운데 그곳의 사본보다 `generatedAt`이 늦거나 그곳에 없는 것을 복사하고, 목록을 다시 만들어 검사합니다(노트 오류는 경고). 커밋 메시지는 `Archive parallel timeline session YYYY-MM-DD`이고, 여러 날짜면 `Archive parallel timeline sessions D1, D2`입니다. 세션은 그대로이고 목록만 바뀌면(노트 제목이 바뀐 경우 등) `Refresh parallel timeline index`입니다.
8. 7단계가 원래 저장소의 main에 push했을 때만 `scripts/request-parallel-pages-build.js`가 공개된 `data/parallel/index.json`이 방금 보관한 목록과 같은지 해시로 확인합니다. main에 push하면 Pages 빌드가 저절로 시작되는 것으로 보이므로, 먼저 약 2.5분 동안(5초 간격 30번) 공개 파일을 확인합니다. 그래도 다르면 Pages 빌드를 한 번 요청하고 약 4분 동안(5초 간격 48번) 다시 확인합니다.

- 6·7단계의 push는 최대 3번 시도하며, 거절되면 그 브랜치의 최신 커밋에서 처음부터 다시 만듭니다. 세 번 모두 실패해도 강제 push는 하지 않고 작업을 실패로 끝냅니다.
- 장중 회차는 main에 커밋하지 않으므로 Pages 빌드를 일으키지 않습니다. 화면은 data 브랜치를 raw.githubusercontent.com에서 바로 읽습니다.
- 수집 작업은 예약·push 실행이 `parallel-timeline-auto`, 수동 실행이 `parallel-timeline-manual` 그룹에서 하나씩 차례로 돌며, 진행 중인 실행을 취소하지 않습니다. 다만 GitHub는 그룹마다 대기 실행을 하나만 두므로, 대기 실행이 있을 때 새 실행이 들어오면 앞의 대기 실행은 취소됩니다. 수동 실행은 그룹이 달라 예약·push 실행 때문에 취소되지는 않지만, 수동 실행이 대기 중일 때 다른 수동 실행을 시작하면 앞의 것이 취소됩니다. 취소된("cancelled") 수동 실행은 다시 실행합니다. 점검 모드는 `parallel-timeline-probe` 그룹을 씁니다. 두 그룹의 실행이 겹쳐도 6·7단계가 `generatedAt`이 늦은 세션을 남깁니다.
- 워크플로의 기본 권한은 읽기 전용이고, 수집 작업만 `contents: write`와 `pages: write`를 받습니다. 체크아웃은 인증 정보를 남기지 않고, 토큰은 6·7단계(push)와 8단계(Pages API)의 환경에만 넣으므로 테스트와 수집기는 토큰 없이 실행됩니다. 수집 작업은 20분 안에 끝나지 않으면 중단됩니다. 새 비밀값은 필요하지 않습니다.

- 바닥글, 차트 설명, PNG 아래쪽 줄에 출처와 Coin Metrics 라이선스를 표시합니다. 이 표시를 지우지 않습니다.
- 저장소와 Pages가 공개되어 있으므로 수집한 시세 파일(main과 data 브랜치)도 누구나 볼 수 있습니다. 화면에는 검색 제외 표시(noindex)를 둡니다. 상업적 이용이나 대량 재배포처럼 개인 비상업 열람을 넘는 용도로 쓰려면 각 제공자의 약관과 라이선스를 따로 확인해야 합니다.
- 수집기와 점검 모드의 모든 요청은 실행하는 저장소를 밝히는 정직한 User-Agent를 단 평범한 요청입니다. 형식은 `chatgpt-dot-monitoring-hub/2.0 (+https://github.com/<저장소>)`이며, Actions에서는 실행하는 저장소(`GITHUB_REPOSITORY`)를, 그 밖에서는 원래 저장소를 적습니다. 그래서 원래 저장소의 요청은 `chatgpt-dot-monitoring-hub/2.0 (+https://github.com/tlzkrh1029/chatgpt-dot-monitoring-hub)`이고, 포크의 요청은 포크 이름을 밝힙니다. 리디렉션은 따라가지 않습니다. 쿠키·crumb 조작이나 브라우저 위장처럼 요청 제한과 봇 확인을 피하는 방법은 쓰지 않습니다.
- Yahoo에는 기호마다 15분봉을 한 번씩 차례로 요청하고, 요청 사이에 0.5초 이상 쉬며, 요청 하나를 20초까지 기다립니다. 일봉은 그 세션의 전일 종가를 일봉에서 아직 확인하지 못한 계열만 요청합니다(기준 이름이 `전일 종가`인 계열은 다시 요청).
- 5xx 응답이나 응답 없음(시간 초과, 연결 실패)은 3초 뒤에 한 번만 다시 시도합니다.
- 다음 경우에는 그 회차의 남은 Yahoo 요청을 모두 멈추고, 남은 Yahoo 계열의 `note`에 이유를 남깁니다.

| 경우 | note |
|---|---|
| HTTP 429(요청 제한) | `Yahoo 요청 제한(HTTP 429)` |
| HTTP 401·403·451이나 리디렉션(3xx) | `Yahoo 접근 거부(HTTP 403)`처럼 상태 코드를 적음 |
| JSON이 아닌 200 응답(동의 화면이나 봇 확인 화면 등) | `Yahoo 접근 거부(JSON 아닌 응답)` |
| 응답 없는 요청이 두 번 연속(각각 다시 시도한 뒤) | `Yahoo 요청 중단(연속 응답 없음)` |
| 회차가 시작한 지 6분이 지남(이후 새 요청을 보내지 않음) | `Yahoo 요청 중단(수집 6분 초과)`, Coin Metrics는 `Coin Metrics 요청 중단(수집 6분 초과)` |

- 직전 회차에서 Yahoo가 모든 Yahoo 계열을 429나 접근 거부로 막았다면, 그 파일을 만든 지 30분이 지나기 전에 시작한 회차는 Yahoo에 요청하지 않고 `Yahoo 요청 보류(직전 회차 거부)`를 남깁니다. 이 보류는 거부로 치지 않으므로, 그다음 회차는 다시 요청합니다.
- Coin Metrics에는 다섯 자산을 한 번에 요청합니다. 다음 쪽은 같은 호스트일 때만 5쪽까지 따라갑니다. 요청이 실패하거나 응답에 없는 자산은 그 계열만 Yahoo 대체 기호로 받고, 계열의 `note`에 실패 사유와 "Yahoo 대체"를 남깁니다(예: `Coin Metrics 자료 없음 · Yahoo 대체`).

## 실패할 때

| status | 언제 | points | note |
|---|---|---|---|
| `ok` | 이번 회차에 새로 받음 | 새 값 | 보통 비어 있음. 크립토를 Yahoo로 대체했으면 그 사유, 앞부분을 이전 점으로 채웠으면 `새 응답에 앞부분 없음 · 이전 자료로 보충` |
| `stale` | 요청이 실패했거나, 새 응답에 점이 없거나 저장된 점보다 일찍 끝나서 같은 날짜의 이전 점을 남김 | 이전 값(새 값과 합침) | 실패 사유, `새 응답에 자료 없음 · 이전 자료 유지`, `새 응답에 일부 자료 없음 · 이전 자료 유지` |
| `missing` | 실패 없이 응답했지만 구간 안에 점이 없고, 이어받을 이전 점도 없음(휴장, 개장 전) | `[]` | `자료 없음(휴장 또는 개장 전)` |
| `error` | 실패했고 이어받을 이전 점이 없음 | `[]` | 실패 사유, `전일 종가 확인 실패`, `기준값 없음` |

새 응답과 저장된 점은 다음 규칙으로 합칩니다.

- 같은 출처의 새 응답이 저장된 점보다 늦게 시작하거나 일찍 끝나면, 새 응답의 시간 범위 밖에 있는 저장된 점을 그대로 둡니다. 범위 안에서는 새 값을 쓰고, 모든 등락률을 기준값으로 다시 계산합니다. 뒷부분을 저장된 점으로 남기면 `stale`(`새 응답에 일부 자료 없음 · 이전 자료 유지`)이 되어 다음 회차가 다시 시도하고, 앞부분만 채우면 `ok`(`새 응답에 앞부분 없음 · 이전 자료로 보충`)입니다.
- 새 응답에 점이 하나도 없으면 저장된 점을 모두 남기고 `stale`(`새 응답에 자료 없음 · 이전 자료 유지`)로 둡니다. 저장된 점도 없을 때만 `missing`입니다.
- 크립토를 Yahoo 대체 기호로 받았는데 다른 출처의 저장된 점보다 일찍 끝나면, 저장된 계열을 그대로 두고 `stale`로 둡니다.
- 점은 받았지만 기준값을 정하지 못하면(전일 종가 계열의 일봉 요청이 실패했고 15분봉 응답에도 전일 종가가 없는 경우 등) 받은 점을 쓰지 않습니다. 저장된 점이 있으면 `stale`, 없으면 `error`이고, note는 `전일 종가 확인 실패` 또는 `기준값 없음`입니다.
- 크립토의 note에는 앞에 대체 사유가 붙을 수 있습니다(예: `Coin Metrics 자료 없음 · Yahoo 대체 · 자료 없음(휴장 또는 개장 전)`).

화면은 상태를 다음처럼 표시합니다. `stale`·`error` 계열은 상태 표시에서 " · 일부 지연 n"(최종이면 " · 일부 수집 실패 n")으로 세고, 자동 항목에서는 뺍니다. 바닥글의 "계열별 기준과 상태"에는 상태 이름("정상", "이전 자료 유지", "자료 없음", "수집 실패")과 note가 나옵니다.

| status | 범례 | 그 밖의 표시 |
|---|---|---|
| `stale` | " · 09:45까지"(구간 안에 점이 없으면 " · 수집 지연") | 오른쪽 이름표를 흐리게 쓰고 "(09:45)"를 붙임. 시간표 열 머리에 "09:45까지". 차트 설명에 "최근 수집 실패로 이전 자료 표시: 코스피(09:45까지)" |
| `missing` | " · 자료 없음" | |
| `error` | " · 수집 실패" | 시간표 열 머리에 "수집 실패". 차트 설명에 "수집 실패: 항셍" |

- 수집기는 값을 지어내지 않습니다. 빈 시간을 보간하지 않고, 실패한 계열을 다른 기호로 메우지 않습니다. 크립토의 Yahoo 대체만 정해 둔 예외이며, 이때도 `source`에 실제로 쓴 기호를 남깁니다.
- 실패 사유는 계열의 `note`에 남고, 바닥글의 "계열별 기준과 상태"에서 볼 수 있습니다. Actions 실행 요약에도 `stale`·`error` 계열이 `parallel <계열 id>` 경고로 나오며, 이전 세션을 마감한 회차의 경고에는 날짜가 붙습니다.
- 화면이 파일을 받지 못하거나 검증에 실패하면 마지막 정상 자료를 그대로 두고 상태를 "수신 실패 · 마지막 정상 자료"로 바꾼 뒤 다시 시도합니다(위 "도구와 갱신").
- 노트를 받지 못하거나 노트가 검증에 실패하면 같은 날짜에서 직전에 받은 노트를 유지합니다. 보여 줄 노트가 없으면 "분석 노트를 불러오지 못했습니다(사유). 잠시 후 다시 시도합니다."를 띄우고 다시 시도합니다. "이 날짜의 분석 노트가 없습니다."는 주소들이 404로 답해 노트 파일이 없다고 확인될 때만 나옵니다.
- 이 탭의 테스트가 실패하면 그 회차는 수집하지 않습니다. 수집한 index나 세션이 검증에 실패하면 게시하지 않으며, 노트의 오류는 게시를 막지 않습니다. push가 세 번 모두 실패해도 강제로 덮어쓰지 않고 작업을 실패로 끝냅니다. Pages 확인이 실패해도 커밋한 자료는 Git에 남습니다.
- 최종 파일에 `stale`이나 `error` 계열이 남아 있으면, 그 파일을 만든 지 60분이 지난 뒤의 회차가 다시 수집합니다(위 "실행 시각"). 다음 날 08:00 KST부터는 날짜를 주지 않은 실행이 새 날짜를 수집하므로, 그때도 남아 있으면 수동 실행에서 그 날짜를 넣어 다시 수집합니다. 이때는 `force`를 켜지 않아도 됩니다.
- `missing`은 실패로 치지 않으므로, 최종 파일의 `missing` 계열은 다시 수집하지 않습니다. 휴장이 아닌데 `missing`이 남았다면 `force`를 켠 수동 실행으로 다시 수집합니다.
- 다시 수집하면 저장된 값이 제공자의 지금 응답으로 바뀝니다. Coin Metrics는 지난 기준가격을 고쳐 내기도 하므로, 확정된 날짜를 `force`로 다시 수집하면 크립토 값과 크립토 기준값이 조금 달라질 수 있습니다(11/4 세션도 다시 수집했을 때 크립토 값 일부와 ZEC 기준값이 바뀌었습니다). 새 응답에 없는 앞뒤 구간의 점은 위 규칙대로 남습니다.

## 분석 노트 쓰기

노트는 선택 사항입니다. 노트가 없어도 차트, 자동 항목, 시간표는 보입니다.

### 차례

1. 그 날짜의 세션 파일이 있는지 확인합니다. 화면은 세션 파일이 있는 날짜에서만 노트를 읽습니다. 수집 중인 날짜의 세션 파일은 data 브랜치(`parallel-data`)에만 있습니다.
2. 아래 틀을 main의 `data/parallel/notes/YYYY-MM-DD.json`으로 복사하고 `date`를 파일 이름과 같게 맞춥니다. 필수 필드는 `schemaVersion`, `kind`, `date`뿐이므로 쓰지 않는 필드는 지웁니다.
3. 차트와 겹치는 수치는 세션 파일의 값에 맞춥니다. 보도나 거래소 API에서 가져온 외부 수치는 단락 출처나 `footnote`에 출처와 미확인 여부를 남깁니다. 시각이 겹친다는 이유만으로 인과를 단정하지 않습니다.
4. `node scripts/validate-parallel.js`(노트 오류도 실패로 봄)와 `npm run test:parallel`을 통과시킨 뒤 노트 파일만 main에 커밋합니다.
5. 노트를 main에 push하면 워크플로가 시작되어 data 브랜치의 노트 사본과 두 브랜치의 날짜 목록(제목, `hasNotes`)을 맞춥니다. 화면은 노트를 main에서 먼저 읽으므로 새로 열거나 다음에 자료를 읽을 때 노트를 보여 주며, 목록이 갱신되기 전에도 선택한 날짜에는 노트 제목이 보입니다. 그 사이 `validate-parallel.js`는 index가 노트보다 늦은 것을 오류가 아닌 경고로만 알립니다.
6. 워크플로는 노트의 오류 때문에 시세 게시를 멈추지 않습니다. 대신 잘못된 노트는 Actions에 `parallel notes` 경고로 나오고 화면에도 보이지 않으므로, 경고를 보면 바로 고칩니다.

### 필드

| 필드 | 화면 위치 | 규칙 |
|---|---|---|
| `schemaVersion`, `kind`, `date` | (필수) | `3`, `"notes"`, 파일 이름과 같은 KST 날짜 |
| `title` | 제목, 날짜 목록, PNG 머리글 | 생략하면 "시장 병렬 타임라인" |

| `asOf`, `author` | 바닥글의 "분석 노트: 작성 … · HH:MM KST 기준", 자동 항목 위의 기준 시각 줄, PNG 아래 줄 맨 앞의 작성자 | `asOf`는 UTC 시각 |
| `display` | 차트, 시간표, 자동 항목의 표시 구간 | KST `HH:MM`, start < end. 세션 구간 밖은 잘림. 생략하면 세션 구간 |
| `headline` | 한 줄 | |
| `events` | 차트의 사건선, 사건 목록 | 아래 "사건" 참고 |

| `sections` | 세부·읽기 카드(넓은 화면에서 2열) | `{id, heading, items}`. heading 필수. id를 영문·숫자로 쓰면 `#note-asia` 같은 앵커가 됨 |
| `watch` | 볼 것 | 문자열 배열 |
| `story` | 스토리텔링 | `{text, sources}`. 단락마다 "출처: …" 줄이 붙음. source는 `{label, url}`이고 url은 생략 가능 |
| `verdict` | 판정 | |
| `footnote` | 바닥글 | 미확인 사항과 한계 |

### 사건

| 필드 | 규칙 |
|---|---|
| `at` | 필수. 사건 시각(UTC). 차트의 점선 위치 |
| `label` | 필수. 차트 위 첫째 줄. 8자 안팎으로 짧게 |
| `sub` | 차트 위 둘째 줄 |
| `id` | 노트 안에서 겹치지 않는 식별자 |
| `kind` | 아래 종류 중 하나. 사건 목록에 이름표로 표시 |
| `end` | 구간의 끝 시각. `at`보다 늦어야 하고, 있으면 띠로 그림. `band`에는 필수 |
| `source`, `url` | 사건 목록의 출처 링크. url은 `https://`만 허용 |
| `detail` | 사건 목록에만 나오는 설명 |
| `alts` | 같은 사건의 다른 출처 시각 `[{source, at, url}]`. source만 필수. 목록에 "다른 시각: DDHQ 09:18"처럼 나오고 차트에는 그리지 않음 |

| kind | 화면 표시 | 쓰임 |
|---|---|---|
| `call` | 호출 | 당선 판단 같은 결과 호출 |
| `projection` | 투영 | 다수당 같은 전체 결과 투영 |
| `statement` | 발언 | 인물의 발언이나 발표 |
| `concession` | 승복 | 패배 인정 |
| `prediction` | 예측 | 예측시장이나 전망의 변화 |
| `band` | 구간 | 시작과 끝이 있는 구간(파란 띠) |
| `other` | 기타 | 그 밖의 사건 |

- 시각은 KST에서 9시간을 빼서 UTC로 적습니다. 11/5 09:39 KST는 `2026-11-05T00:39:00Z`이고, 11/5 08:51 KST는 날짜가 하루 앞선 `2026-11-04T23:51:00Z`입니다.
- 차트는 배열에 넣은 사건 중 표시 구간 안에 있는 것을 모두 그립니다. 그러므로 차트에 보일 사건만 골라 넣습니다. 표시 구간 밖의 사건은 사건 목록에만 나오고, 띠는 구간과 겹치는 부분만 그립니다.
- 라벨이 길거나 사건이 몰려 세 줄 안에 겹치지 않게 놓을 수 없으면 차트는 이름 대신 번호와 번호별 이름 목록을 표시합니다. 이름을 짧게 쓰면 차트에 글자로 남습니다.

### 글쓰기 규칙

- 모든 텍스트는 일반 텍스트이고, 쓸 수 있는 표시는 `**굵게**` 하나뿐입니다. 화면은 모든 글자를 이스케이프한 뒤 `**x**`만 `<strong>x</strong>`로 바꿉니다. HTML 태그나 마크다운 링크는 글자 그대로 보입니다.
- 굵게 표시는 `headline`, `observations`, `sections`의 제목과 항목, `watch`, `story`의 본문, `verdict`, `footnote`, 사건 목록의 `label`·`sub`·`detail`에 적용됩니다. `title`, `subtitle`과 차트 위 글자에서는 `**`만 빠지고 일반 글자로 보입니다.
- 링크는 본문에 넣지 않고 `url` 필드에만 `https://` 주소로 넣습니다.
- 텍스트 필드 하나는 4,000자를 넘을 수 없습니다.
- 화면 글에는 긴 줄표(em dash)를 쓰지 않고 `·`나 `:`를 씁니다. 음수에는 하이픈 대신 마이너스 기호(−)를 씁니다.

## 수동 실행

GitHub의 **Actions → Update parallel market prices → Run workflow**에서 브랜치(보통 `main`)를 고르고 입력값을 채웁니다.

| 입력 | 값 | 기본값 |
|---|---|---|
| `mode` | `collect`(수집) 또는 `probe`(읽기 전용 점검) | `collect` |
| `date` | 수집할 KST 날짜 `YYYY-MM-DD`. 오늘보다 늦은 날짜를 넣으면 실행이 실패함 | 비우면 현재 세션(구간 시작 전이면 전날). 주말 날짜는 넣었을 때만 수집 |
| `start`, `end` | 수집 구간 KST `HH:MM` | 비우면 기존 파일의 구간, 파일이 없으면 `08:00`, `16:00` |
| `force` | 최종 파일 건너뛰기와 60분 재수집 대기를 무시 | 끔 |
| `replace_window` | `start`·`end`가 기존 파일의 구간과 다를 때 그 파일을 새 구간으로 바꿈(저장된 점은 버림) | 끔 |

- `force`를 끈 수동 실행은 예약 실행과 같은 건너뛰기 규칙을 따릅니다(10분 제한은 push 실행에만 있습니다). 그래서 수집 중인 날짜는 바로 수집하고, 확정된 날짜는 `stale`·`error`가 남아 있고 만든 지 60분이 지났을 때만 다시 수집합니다. 문제가 없는 확정 날짜를 다시 받으려면 `force`를 켭니다. 이때 저장된 값이 제공자의 지금 응답으로 바뀝니다(위 "실패할 때").
- 수동 수집도 data 브랜치에 게시하고, 최종 세션은 실행한 브랜치에 보관합니다. main에서 실행하면 `parallel-data`, 다른 브랜치에서 실행하면 `parallel-data-<브랜치 이름>`에 게시하며, 화면은 `parallel-data`만 읽습니다. Pages 확인은 원래 저장소의 `main`에서만 합니다.
- `start`·`end`를 비우면 기존 파일의 구간을 그대로 쓰므로, 한 번 바꾼 구간은 이후 예약 실행에서도 유지됩니다. 기존 파일과 다른 구간을 넣으면 `replace_window`를 켜지 않는 한 아무것도 요청하지 않고 실패로 끝납니다. `replace_window`를 켜면 저장된 점을 버리므로, 그 회차에 실패한 계열은 점이 없는 `error`가 됩니다.
- 지난 날짜도 다시 수집할 수 있습니다. 다만 Yahoo는 15분봉을 최근 약 60일까지만 주므로, 그보다 오래된 날짜는 다시 받지 못하고 저장된 점이 `stale`로 남습니다. 그러므로 그런 날짜는 다시 수집하지 않습니다.
- `mode`를 `probe`로 두면 수집과 커밋 없이, Actions 실행 환경에서 수집기의 출처에 닿는지만 확인합니다. 어느 브랜치에서나 실행할 수 있습니다.
  - Coin Metrics에는 다섯 자산의 최근 1시간을 한 번 요청하고, Yahoo에는 기호 19개마다 최근 5일의 15분봉과 최근 1개월의 일봉을 요청합니다(최대 39번).
  - 수집기와 같은 User-Agent를 달고 0.7초 이상 간격으로 차례로 요청하며, 다시 시도하지 않고 리디렉션도 따라가지 않습니다.
  - 첫 거부(HTTP 429·401·403·451, 리디렉션, JSON이 아닌 200 응답)에서 바로 멈추고, 응답 없는 요청이 두 번 연속되어도 멈춥니다.
  - 결과는 요청마다 요청 주소, 상태 코드, 걸린 시간, 응답을 요약한 값(봉 수, 첫 봉과 마지막 봉 시각, 전일 종가 등)만 담은 `report.json` 하나이며, 응답 본문은 저장하지 않습니다. 이 파일은 실행 아티팩트 `parallel-source-probe`로 3일 동안 보관되고, 저장소가 공개되어 있으므로 그동안 GitHub에 로그인한 누구나 내려받을 수 있습니다.

## 로컬 미리보기

저장소 루트에서 정적 서버를 띄웁니다.

~~~sh
python3 -m http.server 8000
~~~

브라우저에서 `http://localhost:8000/parallel.html?date=2026-11-04`를 엽니다. 로컬에서는 같은 폴더의 `data/parallel/`만 읽으므로, 커밋하기 전의 노트도 바로 확인할 수 있습니다. main의 `data/parallel/`에는 보관된 최종 세션만 있으므로, 수집 중인 날짜를 보려면 data 브랜치의 세션 파일을 가져와야 합니다(예: `git fetch origin parallel-data` 뒤 `git show origin/parallel-data:data/parallel/sessions/YYYY-MM-DD.json`). 이렇게 가져온 파일은 커밋하지 않습니다. 파일을 `file://`로 직접 열면 브라우저가 자료 읽기를 막으므로 서버를 거쳐야 합니다.

수집기를 로컬에서 실행할 수도 있습니다. 실제 제공자에 요청하므로 필요할 때만 쓰고, 결과를 커밋할지는 따로 판단합니다. 로컬 실행은 원래 저장소 이름을 단 User-Agent를 씁니다. `--dry-run`을 붙이면 받아서 요약만 출력하고 파일은 쓰지 않습니다.

~~~sh
node scripts/collect-parallel.js --date 2026-11-04 --force --dry-run
node scripts/collect-parallel.js --date 2026-11-04 --force
node scripts/collect-parallel.js --rebuild-index --data-dir data/parallel
~~~

## 점검

~~~sh
npm run test:parallel
node scripts/validate-parallel.js
npm test
npm run validate
~~~

- `npm run test:parallel`(`node --test tests/parallel-*.test.js`)은 이 탭의 테스트만 실행합니다. 계산(`parallel-core.js`), 차트, 화면과 그 동작, 수집기, 워크플로와 운영 스크립트, Pages 확인 테스트가 들어 있습니다. 수집기, 점검 모드, Pages 확인 테스트는 `tests/fixtures/parallel/`의 작은 합성 자료와 가짜 응답만 쓰고, 실제 제공자나 GitHub에는 요청하지 않습니다. 워크플로는 이 테스트를 `PARALLEL_SKIP_LIVE_DATA_TESTS=1`과 함께 실행해, 저장소의 실제 자료 파일을 읽는 테스트를 건너뜁니다.
- `node scripts/validate-parallel.js [--notes=warn] [폴더]`는 `data/parallel/`(또는 준 폴더)의 index, 세션, 노트를 검사합니다. 파일 이름과 `date`가 같은지, index가 세션 파일을 빠짐없이 나열하는지도 확인합니다. 종료 코드는 정상이면 0, 오류가 있으면 1, 사용법 오류면 2입니다. `--notes=warn`을 주면 노트의 오류를 경고로만 알립니다.
- `npm test`는 `tests/*.test.js` 전체를 실행하고, `npm run validate`는 기존 상황판의 `data.json`과 다섯 범주 파일, 병렬 타임라인의 자료(노트까지 엄격하게), 선거 결과 파일을 차례로 검사합니다. 이 두 명령은 이 탭의 워크플로가 실행하지 않으므로, 다른 탭의 자료나 테스트가 시세 게시를 막지 않습니다.
- 노트 하나만 빠르게 확인하려면 다음을 실행합니다.

~~~sh
node -e "require('./parallel-core.js').validateNotes(require('./data/parallel/notes/2026-11-04.json')); console.log('ok')"
~~~

- data 브랜치의 자료를 검사하려면 그 브랜치를 별도 작업 폴더로 꺼내 검사기에 폴더를 넘깁니다.

~~~sh
git fetch origin parallel-data
git worktree add --detach ../parallel-data-check origin/parallel-data
node scripts/validate-parallel.js ../parallel-data-check/data/parallel
git worktree remove ../parallel-data-check
~~~
