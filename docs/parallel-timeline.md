# 병렬 타임라인 탭 운영 안내

`parallel.html`은 기존 상황판과 분리된 시장 병렬 타임라인입니다. 화면은 한 KST 날짜의 08:00–16:00을 15분 격자로 나누고, 주식지수, AI·반도체 종목, 크립토, 달러·금의 네 패널이 이 시간축을 함께 씁니다. 시세는 GitHub Actions의 수집기가 `data/parallel/`에 쓰고, 사건선과 해설은 분석가가 날짜별 노트 파일에 씁니다. 화면은 이 파일들을 읽기만 합니다.

## 화면 구성

### 네 패널

| 패널 | 기준 | 계열(원자료 기호) |
|---|---|---|
| 주식지수 | 전일 종가 대비 % | 코스피 `^KS11`, 니케이225 `^N225`, 대만 가권 `^TWII`, 항셍 `^HSI`, 나스닥100 선물 `NQ=F`(08:00 KST 대비) |
| AI·반도체 종목 | 전일 종가 대비 % | SK하이닉스 `000660.KS`, 삼성전자 `005930.KS`, TSMC `2330.TW`, 소프트뱅크 `9984.T`, 어드반테스트 `6857.T` |
| 크립토 | 08:00 KST 대비 % | BTC, ETH, HYPE, ZEC, XMR: Coin Metrics 우선, 실패하면 Yahoo `BTC-USD`, `ETH-USD`, `HYPE32196-USD`, `ZEC-USD`, `XMR-USD` |
| 달러·금 | 08:00 KST 대비 % | 달러지수 `DX-Y.NYB`, 달러/원 `KRW=X`, 달러/엔 `JPY=X`, 금 선물 `GC=F` |

- 전일 종가는 거래소 현지 날짜로 본 직전 거래일의 종가입니다. 전날이 휴장이었던 시장은 그보다 앞선 거래일의 종가가 기준이 되며, 차트 설명에 "11/2 종가 기준: 니케이225·소프트뱅크"처럼 따로 적습니다. 일봉 요청이 실패하면 15분봉 응답에 든 전일 종가를 쓰고 기준 이름을 `전일 종가`로 둡니다.
- 08:00 KST 대비 계열은 08:00 KST의 값을 기준으로 씁니다. 그 값이 없으면 08:00 봉의 시가를, 그것도 없으면 30분 안의 첫 관측값을 쓰고, 기준 이름(`08:00 KST 시가`, `첫 관측 08:30 KST`)에 그 사실을 남깁니다.
- 수집기는 공식 종가를 공식 마감 시각(코스피·니케이 15:30, 대만 14:30)에 찍고, 아직 끝나지 않은 15분봉은 마지막 시세 시각의 실시간 값으로 찍습니다.
- 차트는 관측 간격이 15분보다 길고 125분 이하이면 흐린 점선으로 잇고, 125분보다 길면 잇지 않습니다. 빈 구간을 다른 값으로 채우지 않습니다.

### 사건선

노트의 `events`는 모든 패널을 가로지르는 세로 점선으로 그려지고, 첫 패널 위에 이름 두 줄(`label`, `sub`)이 붙습니다. `end`가 있는 사건은 시작부터 끝까지 파란 띠로 그립니다. 라벨을 세 줄 안에 겹치지 않게 놓을 수 없거나 화면 폭이 640px보다 좁으면 차트는 이름 대신 ①② 같은 번호를 표시하며, 그 번호는 사건 목록의 번호와 같습니다.

### 화면 순서

| 순서 | 영역 | 채우는 곳 |
|---|---|---|
| 1 | 머리글: 제목, 날짜와 구간, 날짜 선택, 상태, 테마, PNG 저장 | `notes.title`, 세션 |
| 2 | 한 줄 | `notes.headline` |
| 3 | 차트 | 세션 시세, `notes.events` |
| 4 | 차트에서 바로 보이는 것 | `notes.observations`, 이어서 "자동" 항목 |
| 5 | 시간표(패널 선택) | 세션에서 자동 계산: 정시별 값, 최저(강조), 마지막 |
| 6 | 세부·읽기 카드 | `notes.sections` |
| 7 | 볼 것 | `notes.watch` |
| 8 | 스토리텔링 | `notes.story`(단락마다 출처 줄) |
| 9 | 판정 | `notes.verdict` |
| 10 | 사건 목록 | `notes.events`(다른 출처의 시각 포함) |
| 11 | 바닥글 | 출처와 라이선스, 작성자와 기준 시각, `notes.footnote`, 계열별 기준과 상태 |

"자동" 항목은 세션 자료로 계산한 사실만 적고 인과를 주장하지 않습니다. 바닥 시각, 가장 가파른 동반 반등, 낙폭 회복률, 가장 깊은 낙폭, 기준선 아래로 거의 내려가지 않은 계열, 후행 움직임, 마지막 값 상위·하위를 최대 7개까지 보여 줍니다. 노트가 없는 날은 차트, 자동 항목, 시간표만 보이고 "이 날짜의 분석 노트가 없습니다"라는 안내가 한 번 나옵니다.

### 도구와 갱신

- 날짜 선택은 수집된 날짜를 최신순으로 보여 줍니다. 주소에 `?date=YYYY-MM-DD`를 붙여도 되고, 붙이지 않으면 가장 최근 날짜를 엽니다.
- 상태 표시는 "실시간 · HH:MM 갱신"(마감 전), "최종"(확정), "수신 실패 · 마지막 정상 자료"(받기나 검증에 실패해 직전 자료를 유지) 중 하나입니다.
- 차트에 포인터를 올리거나 누르면 그 시각의 모든 값이 나옵니다. 차트에 초점을 두면 ← → 키로 15분씩, Home·End 키로 처음과 끝으로 시각을 옮길 수 있습니다.
- 기본 테마는 어두운 화면이고 "밝은 화면" 버튼으로 바꿉니다. 이 선택은 그 브라우저에만 저장됩니다.
- "PNG 저장"은 머리글과 출처 줄을 넣은 밝은 그림(폭 1400px, 2배 해상도)을 내려받고, "어두운 PNG"는 같은 그림을 어두운 테마로 내려받습니다. 파일 이름은 `parallel-timeline-YYYYMMDD.png`와 `parallel-timeline-YYYYMMDD-dark.png`입니다.
- 화면은 선택한 날짜가 최종이 아니면 탭이 보이는 동안 5분마다, 그리고 탭으로 돌아올 때 index, 세션, 노트를 다시 읽습니다. 최종 날짜는 다시 읽지 않습니다.
- 화면을 github.io에서 열면 `raw.githubusercontent.com`에 있는 main의 사본을 먼저 읽고, 실패하면 같은 사이트의 `data/parallel/`을 읽습니다. 그래서 새 커밋은 Pages 빌드를 기다리지 않고 몇 분 안에 보입니다. 다른 주소에서는 같은 사이트의 파일만 읽습니다.

## 자료 위치와 형식

~~~
data/parallel/index.json                 수집기 작성: 날짜 목록
data/parallel/sessions/YYYY-MM-DD.json   수집기 작성: KST 날짜마다 하나
data/parallel/notes/YYYY-MM-DD.json      분석가 작성: 사건과 해설(선택)
~~~

- 세 파일 모두 UTF-8 JSON이고 `schemaVersion`은 3입니다. `kind`는 각각 `index`, `session`, `notes`입니다.
- 시각은 모두 `Z`로 끝나는 UTC ISO 문자열입니다(예: `2026-11-04T00:15:00Z`). 날짜는 KST 달력 날짜이고, KST는 서머타임이 없는 UTC+9입니다.
- 읽는 쪽은 모르는 필드를 무시합니다. 그래도 쓰는 쪽은 이 문서에 없는 필드를 만들지 않습니다.
- 검증 규칙은 `parallel-core.js`의 `validateIndex`, `validateSession`, `validateNotes`에 있습니다. 화면도 같은 함수로 파일을 검사합니다.

### index.json

최상위의 `updatedAt`과 `sessions` 배열로 이루어지며, `sessions`에는 날짜가 최신순으로 들어갑니다. 각 항목은 `date`, `title`(노트 제목, 노트가 없으면 `null`), `final`, `seriesWithData`(점이 있는 계열 수), `updatedAt`, `hasNotes`를 가집니다.

### 세션 파일

| 필드 | 뜻 |
|---|---|
| `date`, `timezone` | KST 날짜, `"Asia/Seoul"` |
| `window` | 수집 구간 `{start, end}`. 기본 08:00–16:00 KST는 전날 `23:00:00Z`부터 당일 `07:00:00Z`까지 |
| `intervalMinutes` | `15` |
| `generatedAt` | 이 파일을 만든 시각 |
| `final` | 구간 끝 + 20분 이후에 만든 파일이면 `true` |
| `series` | 계열 19개. 아래 표 |
| `providers` | 출처 표기: Yahoo Finance, Coin Metrics Community(라이선스 포함) |

| 계열 필드 | 뜻 |
|---|---|
| `id`, `panel`, `label` | 계열 식별자, 패널(`indices`, `ai`, `crypto`, `fx`), 화면 이름 |
| `basis` | `prevClose`(전일 종가 대비) 또는 `windowStart`(08:00 KST 대비) |
| `baseline` | `{value, label}`. label 예: `11/3 종가`, `전일 종가`, `08:00 KST`, `08:00 KST 시가`, `첫 관측 08:30 KST`. value는 `missing`·`error`일 때만 `null`일 수 있음 |
| `source` | 실제로 쓴 원자료 `{provider, symbol}` |
| `status`, `note` | 상태와 사유. 아래 "실패할 때" 참고 |
| `fetchedAt` | 이 계열을 마지막으로 받은 시각 |
| `points` | `[시각, 값, 등락률]`의 배열. 시각 오름차순, 구간 안, 값은 0보다 큼. 등락률(%)은 100 × (값 ÷ 기준값 − 1)을 소수 셋째 자리까지 반올림한 값 |

## 수집기

`scripts/collect-parallel.js`는 한 번 실행될 때 한 날짜의 세션 파일을 만들거나 갱신하고 `index.json`을 다시 맞춥니다. 같은 날짜, 같은 구간의 기존 파일이 있으면 전일 종가 기준값을 재사용하고, 이번에 실패한 계열은 기존 점을 유지합니다. 날짜를 주지 않으면 현재 세션을 수집하며, 그날 구간 시작(기본 08:00 KST) 전에는 전날 세션을 갱신합니다.

### 실행 시각

| 계기 | 시각(KST, 평일) | 목적 |
|---|---|---|
| 예약 | 08:07–16:52, 15분마다(:07 :22 :37 :52) | 장중 수집 |
| 예약 | 17:17, 19:17, 22:17 | 마감 확정과 누락 보충 |
| main push: `data/*.json` | 다른 감시 작업이 범주 파일을 올릴 때 | 예약 실행이 밀리거나 빠질 때의 보조 신호 |
| main push: 워크플로, `scripts/collect-parallel.js`, `parallel-core.js` | 코드가 바뀔 때 | 새 코드로 한 번 실행 |
| 수동 실행 | 언제든 | 아래 "수동 실행" 참고 |

- GitHub의 예약 실행은 부하에 따라 늦어지거나 빠질 수 있습니다. 그래서 예약 시각을 정각에서 7분 늦추고(:07 :22 :37 :52), 매시간 범주 파일을 올리는 다른 감시 작업의 push를 보조 신호로 씁니다.
- 수집기는 `data/parallel/` 아래만 커밋하고 `GITHUB_TOKEN`으로 push하므로, 자신의 커밋으로 이 작업을 다시 실행하지 않습니다.
- 수집기는 다음 경우에 시세를 요청하지 않고 정상 종료합니다. 그래서 추가 실행이 많아도 비용이 작습니다.
  - 기존 파일이 만들어진 지 10분이 지나지 않았을 때
  - 기존 파일이 이미 최종이고, 구간 끝 + 20분 이후에 만들어졌고, `stale`·`error` 계열이 없을 때
  - 날짜를 주지 않았고 현재 세션 날짜가 KST로 토요일이나 일요일일 때(`--date`를 주면 주말 날짜도 수집)
- `--force`를 주면 앞의 두 조건과 관계없이 수집합니다.
- 건너뛰는 회차도 노트 파일을 읽어 `index.json`의 제목과 `hasNotes`를 맞춥니다. 내용이 바뀌었을 때만 파일을 씁니다.
- 구간 끝 + 20분(기본 16:20 KST) 이후에 만든 파일은 `final: true`가 되고, 이후 실행은 그 날짜를 건너뜁니다. 보통 16:22 회차가 최종 파일을 만들고, 17:17·19:17·22:17 회차는 앞 회차들이 빠졌거나 `stale`·`error` 계열이 남았을 때 다시 수집합니다.

### 한 회차의 순서

1. 실행한 브랜치를 전체 이력과 함께 받고 Node 22를 준비합니다.
2. `node scripts/collect-parallel.js`를 실행합니다. 수동 실행은 입력값을 `--date`, `--start`, `--end`, `--force` 인자로 넘깁니다.
3. `npm test`와 `npm run validate`를 실행합니다. 하나라도 실패하면 커밋하지 않습니다.
4. `data/parallel/`이 바뀐 경우에만 그 폴더만 `Update parallel timeline data (YYYY-MM-DD HH:MM KST)` 메시지로 커밋합니다. push하기 전마다 같은 브랜치의 최신 상태를 받아 rebase하고 다시 검증하며, push는 최대 3번 시도합니다. rebase가 충돌하면 push하지 않고 실패로 끝내며, 강제 push는 하지 않습니다.
5. main에서 세션이 최종이거나 수동 실행이면 `scripts/request-parallel-pages-build.js`가 공개된 `data/parallel/index.json`이 저장소의 파일과 같은지 해시로 확인합니다. 다르면 Pages 빌드를 요청하고 반영될 때까지 약 4분 동안 다시 확인합니다. `GITHUB_TOKEN`으로 한 push는 Pages 빌드를 일으키지 않기 때문입니다.

장중 회차는 Pages 빌드를 요청하지 않습니다. 화면이 main의 사본을 raw.githubusercontent.com에서 먼저 읽으므로 빌드를 기다릴 필요가 없습니다. 같은 모드의 실행은 하나씩 차례로 진행하며, 진행 중인 실행을 취소하지 않습니다. 새 비밀값은 필요하지 않습니다.

## 자료 출처와 이용 조건

| 제공자 | 쓰는 계열 | 조건 |
|---|---|---|
| Yahoo Finance 차트 API(15분봉, 전일 종가용 일봉) | 지수, 종목, 선물, 환율, 금, 크립토 대체 | 개인 비상업 열람용. 거래소별 지연 가능 |
| Coin Metrics Community API(`ReferenceRateUSD` 1분 기준가격의 15분 시각 표본) | BTC, ETH, HYPE, ZEC, XMR | CC BY-NC 4.0: 출처 표시, 비상업 이용 |

- 바닥글, 차트 설명, PNG 아래쪽 줄에 출처와 Coin Metrics 라이선스를 표시합니다. 이 표시를 지우지 않습니다.
- 저장소와 Pages가 공개되어 있으므로 수집한 시세 파일도 누구나 볼 수 있습니다. 화면에는 검색 제외 표시(noindex)를 둡니다. 상업적 이용이나 대량 재배포처럼 개인 비상업 열람을 넘는 용도로 쓰려면 각 제공자의 약관과 라이선스를 따로 확인해야 합니다.
- 모든 요청은 정직한 User-Agent `chatgpt-dot-monitoring-hub/2.0 (+https://github.com/tlzkrh1029/chatgpt-dot-monitoring-hub)`를 단 평범한 요청입니다. 쿠키·crumb 조작이나 브라우저 위장처럼 요청 제한과 봇 확인을 피하는 방법은 쓰지 않습니다.
- Yahoo에는 기호마다 15분봉을 한 번씩 차례로 요청하고, 요청 사이에 0.5초 이상 쉬며, 요청 하나를 20초까지 기다립니다. 일봉은 그 세션의 전일 종가를 아직 저장하지 못한 계열만 요청합니다.
- Yahoo가 HTTP 429(요청 제한)를 돌려주면 그 회차의 남은 Yahoo 요청을 모두 멈추고, 남은 계열에 "Yahoo 요청 제한(HTTP 429)"을 기록합니다.
- 5xx 응답이나 네트워크 오류는 3초 뒤에 한 번만 다시 시도합니다.
- Coin Metrics에는 다섯 자산을 한 번에 요청합니다. 요청이 실패하거나 응답에 없는 자산은 그 계열만 Yahoo 대체 기호로 받고, 계열의 `note`에 실패 사유와 "Yahoo 대체"를 남깁니다.

## 실패할 때

| status | 뜻 | points | 화면 |
|---|---|---|---|
| `ok` | 이번 회차에 새로 받음 | 새 값 | "정상" |
| `stale` | 이번 회차에 실패해 같은 날짜의 이전 점을 유지 | 이전 값 | "이전 자료 유지", 차트 설명에 "최근 수집 실패로 이전 자료 표시" |
| `missing` | 실패는 없지만 자료가 없음(휴장, 개장 전) | `[]` | 범례에 "· 자료 없음", note는 "자료 없음(휴장 또는 개장 전)" |
| `error` | 실패했고 이어받을 점도 없음 | `[]` | "수집 실패", 차트 설명에 "수집 실패: 계열 이름" |

- 수집기는 값을 지어내지 않습니다. 빈 시간을 보간하지 않고, 실패한 계열을 다른 기호로 메우지 않습니다. 크립토의 Yahoo 대체만 정해 둔 예외이며, 이때도 `source`에 실제로 쓴 기호를 남깁니다.
- 실패 사유는 계열의 `note`에 남고, 바닥글의 "계열별 기준과 상태"에서 볼 수 있습니다. Actions 실행 요약에도 `stale`·`error` 계열이 경고로 나옵니다.
- 화면이 파일을 받지 못하거나 검증에 실패하면 마지막 정상 자료를 그대로 두고 상태를 "수신 실패 · 마지막 정상 자료"로 바꿉니다. 노트 파일이 검증에 실패하면 직전에 받은 노트를 유지하고, 처음 여는 경우에는 노트를 표시하지 않습니다.
- 테스트나 검증이 실패하면 수집 결과를 커밋하지 않습니다. push가 세 번 모두 실패해도 강제로 덮어쓰지 않고 작업을 실패로 끝냅니다. Pages 확인이 실패해도 커밋한 자료는 Git에 남습니다.
- 최종 파일에 `stale`이나 `error` 계열이 남아 있으면 그날 이후의 실행이 10분 제한을 지키며 다시 수집합니다. 다음 날 08:00 KST가 지나도 남아 있으면 수동 실행에서 그 날짜를 넣어 다시 수집합니다.

## 분석 노트 쓰기

노트는 선택 사항입니다. 노트가 없어도 차트, 자동 항목, 시간표는 보입니다.

### 차례

1. 그 날짜의 세션 파일(`data/parallel/sessions/YYYY-MM-DD.json`)이 있는지 확인합니다. 화면은 세션 파일이 있는 날짜에서만 노트를 읽습니다.
2. 아래 틀을 `data/parallel/notes/YYYY-MM-DD.json`으로 복사하고 `date`를 파일 이름과 같게 맞춥니다. 필수 필드는 `schemaVersion`, `kind`, `date`뿐이므로 쓰지 않는 필드는 지웁니다.
3. 차트와 겹치는 수치는 세션 파일의 값에 맞춥니다. 보도나 거래소 API에서 가져온 외부 수치는 단락 출처나 `footnote`에 출처와 미확인 여부를 남깁니다. 시각이 겹친다는 이유만으로 인과를 단정하지 않습니다.
4. `npm test`와 `npm run validate`를 통과시킨 뒤 노트 파일만 커밋합니다.
5. 화면은 다음에 자료를 읽을 때 노트를 보여 줍니다. 날짜 목록의 제목과 `hasNotes`는 수집기가 다음에 실행될 때(수집을 건너뛰는 회차 포함) `index.json`에 반영되며, 선택한 날짜에는 그 전에도 노트 제목이 보입니다. 그 사이 `npm run validate`는 index가 노트보다 늦은 것을 오류가 아닌 경고로만 알립니다.

### 틀

모든 필드를 넣은 예입니다. 이대로 검증을 통과하며, 날짜와 내용만 바꿔 씁니다.

~~~json
{
  "schemaVersion": 3,
  "kind": "notes",
  "date": "2026-11-05",
  "title": "사건 이름 × 아시아 증시 × 크립토",
  "subtitle": "세로 점선 = 사건 시각 · 파란 띠 = 구간 이름(13:20~13:35)",
  "asOf": "2026-11-05T06:00:00Z",
  "author": "작성자",
  "display": { "start": "08:00", "end": "16:00" },
  "headline": "한두 문장 요약입니다. 강조는 **이렇게** 씁니다.",
  "events": [
    {
      "id": "first",
      "at": "2026-11-05T00:39:00Z",
      "label": "짧은 이름",
      "sub": "보조 설명",
      "kind": "call",
      "source": "출처 이름",
      "url": "https://example.com/source",
      "detail": "사건 목록에만 나오는 설명",
      "alts": [
        { "source": "다른 출처", "at": "2026-11-05T00:18:00Z", "url": "https://example.com/other" }
      ]
    },
    {
      "id": "range",
      "at": "2026-11-05T04:20:00Z",
      "end": "2026-11-05T04:35:00Z",
      "label": "구간 이름",
      "sub": "보조 설명",
      "kind": "band",
      "source": "출처 이름",
      "url": "https://example.com/band"
    }
  ],
  "observations": ["차트에서 바로 보이는 사실 한 가지"],
  "sections": [
    { "id": "asia", "heading": "아시아 증시 세부", "items": ["항목"] },
    { "id": "crypto", "heading": "크립토 세부", "items": ["항목"] },
    { "id": "read", "heading": "읽기", "items": ["항목"] }
  ],
  "watch": ["다음에 볼 시각이나 가격"],
  "story": [
    {
      "text": "스토리텔링 단락 하나",
      "sources": [
        { "label": "기사 이름", "url": "https://example.com/article" },
        { "label": "Yahoo Finance 15분봉" }
      ]
    }
  ],
  "verdict": "판정 한두 문장",
  "footnote": "미확인: 확인하지 못한 수치와 시각"
}
~~~

### 필드

| 필드 | 화면 위치 | 규칙 |
|---|---|---|
| `schemaVersion`, `kind`, `date` | (필수) | `3`, `"notes"`, 파일 이름과 같은 KST 날짜 |
| `title` | 제목, 날짜 목록, PNG 머리글 | 생략하면 "시장 병렬 타임라인" |
| `subtitle` | PNG 머리글의 부제 | 생략하면 "세로 점선 = 사건 시각 · 15분봉" |
| `asOf`, `author` | 바닥글의 "분석 노트: 작성 … · HH:MM KST 기준" | `asOf`는 UTC 시각 |
| `display` | 차트, 시간표, 자동 항목의 표시 구간 | KST `HH:MM`, start < end. 세션 구간 밖은 잘림. 생략하면 세션 구간 |
| `headline` | 한 줄 | |
| `events` | 차트의 사건선, 사건 목록 | 아래 "사건" 참고 |
| `observations` | 차트에서 바로 보이는 것(자동 항목보다 위) | 문자열 배열 |
| `sections` | 세부·읽기 카드(넓은 화면에서 2열) | `{id, heading, items}`. heading 필수. id를 영문·숫자로 쓰면 `#note-asia` 같은 앵커가 됨 |
| `watch` | 볼 것 | 문자열 배열 |
| `story` | 스토리텔링 | `{text, sources}`. 단락마다 "출처: …" 줄이 붙음. source는 `{label, url}`이고 url은 생략 가능 |
| `verdict` | 판정 | |
| `footnote` | 바닥글 | 미확인 사항과 한계 |

### 사건

| 필드 | 규칙 |
|---|---|
| `at` | 필수. 사건 시각(UTC). 차트의 점선 위치 |
| `label` | 필수. 차트 위 첫째 줄. 8자 안팎으로 짧게 |
| `sub` | 차트 위 둘째 줄 |
| `id` | 노트 안에서 겹치지 않는 식별자 |
| `kind` | 아래 종류 중 하나. 사건 목록에 이름표로 표시 |
| `end` | 구간의 끝 시각. `at`보다 늦어야 하고, 있으면 띠로 그림. `band`에는 필수 |
| `source`, `url` | 사건 목록의 출처 링크. url은 `https://`만 허용 |
| `detail` | 사건 목록에만 나오는 설명 |
| `alts` | 같은 사건의 다른 출처 시각 `[{source, at, url}]`. source만 필수. 목록에 "다른 시각: DDHQ 09:18"처럼 나오고 차트에는 그리지 않음 |

| kind | 화면 표시 | 쓰임 |
|---|---|---|
| `call` | 호출 | 당선 판단 같은 결과 호출 |
| `projection` | 투영 | 다수당 같은 전체 결과 투영 |
| `statement` | 발언 | 인물의 발언이나 발표 |
| `concession` | 승복 | 패배 인정 |
| `prediction` | 예측 | 예측시장이나 전망의 변화 |
| `band` | 구간 | 시작과 끝이 있는 구간(파란 띠) |
| `other` | 기타 | 그 밖의 사건 |

- 시각은 KST에서 9시간을 빼서 UTC로 적습니다. 11/5 09:39 KST는 `2026-11-05T00:39:00Z`이고, 11/5 08:51 KST는 날짜가 하루 앞선 `2026-11-04T23:51:00Z`입니다.
- 차트는 배열에 넣은 사건 중 표시 구간 안에 있는 것을 모두 그립니다. 그러므로 차트에 보일 사건만 골라 넣습니다. 표시 구간 밖의 사건은 사건 목록에만 나오고, 띠는 구간과 겹치는 부분만 그립니다.
- 라벨이 길거나 사건이 몰려 세 줄 안에 겹치지 않게 놓을 수 없으면 차트는 이름 대신 번호를 표시합니다. 이름을 짧게 쓰면 차트에 글자로 남습니다.

### 글쓰기 규칙

- 모든 텍스트는 일반 텍스트이고, 쓸 수 있는 표시는 `**굵게**` 하나뿐입니다. 화면은 모든 글자를 이스케이프한 뒤 `**x**`만 `<strong>x</strong>`로 바꿉니다. HTML 태그나 마크다운 링크는 글자 그대로 보입니다.
- 굵게 표시는 `headline`, `observations`, `sections`의 제목과 항목, `watch`, `story`의 본문, `verdict`, `footnote`, 사건의 `label`·`sub`·`detail`에 적용됩니다. `title`과 차트 위 글자에서는 `**`만 빠지고 일반 글자로 보입니다.
- 링크는 본문에 넣지 않고 `url` 필드에만 `https://` 주소로 넣습니다.
- 텍스트 필드 하나는 4,000자를 넘을 수 없습니다.
- 화면 글에는 긴 줄표(em dash)를 쓰지 않고 `·`나 `:`를 씁니다.

## 수동 실행

GitHub의 **Actions → Update parallel market prices → Run workflow**에서 브랜치(보통 `main`)를 고르고 입력값을 채웁니다.

| 입력 | 값 | 기본값 |
|---|---|---|
| `mode` | `collect`(수집) 또는 `probe`(읽기 전용 점검) | `collect` |
| `date` | 수집할 KST 날짜 `YYYY-MM-DD` | 비우면 현재 세션(구간 시작 전이면 전날) |
| `start`, `end` | 수집 구간 KST `HH:MM` | 비우면 `08:00`, `16:00` |
| `force` | 10분 제한과 최종 파일 건너뛰기를 무시 | 켬 |

- 수동 실행은 `force`가 기본으로 켜져 있어 바로 수집합니다. 끄면 예약 실행과 같은 건너뛰기 규칙을 따릅니다.
- 수동 수집은 실행한 브랜치에 커밋합니다. Pages 빌드 요청과 공개 파일 확인은 `main`에서만 합니다.
- `start`·`end`로 구간을 바꾼 날짜도 그 파일이 최종이 되기 전에는 다음 예약 실행이 기본 구간(08:00–16:00)으로 다시 씁니다. 구간 변경은 이미 끝난 날짜에 쓰는 것이 안전합니다.
- 지난 날짜도 다시 수집할 수 있습니다. 다만 Yahoo는 15분봉을 최근 약 60일까지만 주므로, 그보다 오래된 날짜는 다시 받지 못합니다.
- `mode`를 `probe`로 두면 수집과 커밋 없이 모든 기호의 응답 상태만 확인합니다. 어느 브랜치에서나 실행할 수 있고, 원본 응답은 3일 동안 보관되는 실행 아티팩트(`parallel-source-probe`)로만 남기며 Git에 넣지 않습니다.

## 로컬 미리보기

저장소 루트에서 정적 서버를 띄웁니다.

~~~sh
python3 -m http.server 8000
~~~

브라우저에서 `http://localhost:8000/parallel.html?date=2026-11-04`를 엽니다. 로컬에서는 같은 폴더의 `data/parallel/`만 읽으므로, 커밋하기 전의 노트도 바로 확인할 수 있습니다. 파일을 `file://`로 직접 열면 브라우저가 자료 읽기를 막으므로 서버를 거쳐야 합니다.

수집기를 로컬에서 실행할 수도 있습니다. 실제 제공자에 요청하므로 필요할 때만 쓰고, 결과를 커밋할지는 따로 판단합니다. `--dry-run`을 붙이면 받아서 요약만 출력하고 파일은 쓰지 않습니다. 모든 옵션은 `--help`로 볼 수 있습니다.

~~~sh
node scripts/collect-parallel.js --date 2026-11-04 --force --dry-run
node scripts/collect-parallel.js --date 2026-11-04 --force
~~~

## 점검

~~~sh
npm test
npm run validate
~~~

- `npm test`는 `tests/*.test.js` 전체를 실행합니다. 병렬 타임라인의 계산(`parallel-core.js`), 차트, 화면, 수집기 테스트도 함께 실행됩니다. 수집기 테스트는 `tests/fixtures/parallel/`의 작은 합성 자료와 가짜 응답만 쓰고, 실제 제공자에는 요청하지 않습니다.
- `npm run validate`는 기존 상황판의 `data.json`과 다섯 범주 파일, `data/parallel/`의 index·세션·노트, 선거 결과 파일을 차례로 검사합니다. 병렬 타임라인 쪽은 파일 이름과 `date`가 같은지, index가 세션 파일을 빠짐없이 나열하는지도 확인합니다.
- 노트 하나만 빠르게 확인하려면 다음을 실행합니다.

~~~sh
node -e "require('./parallel-core.js').validateNotes(require('./data/parallel/notes/2026-11-04.json')); console.log('ok')"
~~~
