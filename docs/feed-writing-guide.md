# 새 소식 피드 작성 규칙

이 문서는 다섯 감시 작업이 범주 파일의 `feed` 항목을 쓸 때 따르는 문장 규칙입니다. README에 적힌 게시 계약(필드, 길이, URL 제한)은 바뀌지 않습니다. 이 규칙은 계약을 통과한 문장이 화면에서 어떻게 읽히는지를 다룹니다.

이미 게시한 기록은 고쳐 쓰지 않습니다. 새로 쓰는 기록부터 적용하며, 정정이 필요하면 지금처럼 별도 기록을 추가합니다.

## 화면에 놓이는 위치

| 필드 | 화면 위치 | 써야 할 내용 |
|---|---|---|
| kind | 범주 이름 옆의 작은 꼬리표 | 아래 고정 어휘 가운데 하나 |
| title | 굵은 제목 | 이번에 확인한 핵심 변화 한 가지 |
| text | 제목 아래 본문 | 무엇이 어떻게 바뀌었는지 설명하는 2–4문장 |
| evidence | 접힌 '확인 방법' | 조회 시각, 출처 사이의 차이, 확인하지 못한 범위 |
| sources | 접힌 '출처' 목록 | 본문을 직접 뒷받침하는 공개 URL |

화면은 기록 시각을 왼쪽 칸에 한국시간으로 표시합니다. 출처에는 OKX, DDHQ, FRED처럼 기관 이름을 자동으로 붙이므로 본문에 URL 설명을 따로 쓰지 않아도 됩니다.

## kind 어휘

kind는 독자에게 "이 기록이 상황을 바꾸는가"를 알려 주는 신호입니다. 주제를 나타내던 '가격·페그 관찰', '개표 관찰' 같은 이름은 제목에 녹여 씁니다.

| kind | 쓰는 경우 | 예 |
|---|---|---|
| 새 사실 | 이번 점검에서 처음 확인했고 상황 판단을 바꾸는 사실 | 당선 판단, 새 사고 공지, 경보 기준 돌파 |
| 정정 | 앞선 기록의 수치나 판단을 바로잡는 기록 | 출처가 피해 추산을 수정함 |
| 누락 보완 | 이미 일어났지만 앞선 기록에서 빠졌던 사실 | 과거 시각의 당선 판단을 뒤늦게 확인함 |
| 참고 | 판단을 바꾸지는 않지만 알아 둘 수치나 맥락 | 정기 시세, 지연된 거시 자료 |
| 확인 제한 | 원문 접근 실패처럼 확인하지 못한 범위 | 공식 결과 페이지 502 오류 |
| 변화 없음 | 점검했지만 직전 기록과 달라진 내용이 없음 | 같은 공지, 같은 수치 |

화면은 '새 사실'과 '정정'을 가장 눈에 띄게, '확인 제한'과 '변화 없음'을 흐리게 표시합니다. 이 목록에 없는 kind도 화면에 나타나지만 신호 표시 없이 일반 글자로 보입니다.

## 문장 규칙

1. 숫자 앞은 띄어 씁니다. "하원241석"이 아니라 "하원 241석", "선두1,796표"가 아니라 "선두 1,796표"로 씁니다. 시간대 약어도 "10:53 UTC"처럼 띄어 씁니다.
2. 본문의 시각은 한국시간으로 씁니다. 원문의 시간대가 판단에 필요할 때만 괄호 안에 한 번 덧붙이고, 초와 밀리초는 쓰지 않습니다.
3. 제목에는 날짜, 시각, 엠대시(—)를 쓰지 않습니다. 두 내용을 이어야 하면 쉼표나 조사로 연결합니다.
4. 본문은 "~다"로 끝나는 완결된 문장으로 씁니다. "축소", "미확인", "동일"처럼 명사로 문장을 끝내지 않습니다.
5. 가운뎃점(·)은 대등한 항목 두세 개를 나열할 때만 씁니다. 대결, 비교, 각각의 관계는 조사로 나타냅니다. "Holscher546,587표·Masterson541,030표"가 아니라 "Holscher 후보는 546,587표, Masterson 후보는 541,030표를 얻었다"로 씁니다.
6. 본문의 주어는 세계에서 일어난 일입니다. 감시 작업이 한 일("조회했다", "대조했다", "재점검했으며")은 evidence에 씁니다.
7. 유보 문장은 본문에 한 문장까지만 둡니다. 독자가 가장 오해하기 쉬운 한계 하나를 고르고, "~로 해석하지 않는다", "~와 구분한다" 같은 작성 원칙은 evidence에 씁니다.
8. 수치는 판단에 필요한 자릿수만 씁니다. 등락률은 소수 둘째 자리, 페그 이탈은 bp 소수 첫째 자리면 충분합니다. 원자료는 sources로 연결합니다.
9. 새 사실이 없는 점검은 kind를 '변화 없음'으로 정하고 본문을 한 문장으로 씁니다. 직전 기록과 같은 문장을 매시간 되풀이하지 않습니다.
10. evidence는 세 문장, 250자 이내로 씁니다.

## 고쳐 쓴 예

### 선거: 띄어쓰기, 관계 표현, 주어

고치기 전(2026-11-04 20:08 기록)입니다.

> **kind** 부분 관찰
> **title** DDHQ 주요 판단 불변, Kansas 공식 비공식 집계 대조
> **text** 상원35·주지사36 경선 개별 페이지를 재점검했으며 Oregon 주지사만 접근 실패했다. DDHQ 하원241D·149R, 상원54D·44R, 주지사27D·20R 및 열람 가능한 경선의 당선 판단은 직전과 같다. Alaska 상원 선두1,796표, Mississippi 상원2,169표, Kansas 주지사5,557표와 CO03 하원 Hurd선두1,211표도 관측값이 같다. > **title** Kansas 주지사 경합, 주정부 집계도 Holscher 5,557표 우세
> **text** Kansas 주정부의 비공식 집계에서 Holscher 후보는 546,587표, Masterson 후보는 541,030표를 얻어 DDHQ 수치와 일치했다. 4,168개 투표구가 모두 보고됐지만 남은 유효표 처리와 공식 인증까지 끝났다는 뜻은 아니다. DDHQ의 당선 판단 합계(민주 대 공화)는 하원 241 대 149, 상원 54 대 44, 주지사 27 대 20으로 직전 점검과 같다.

## 점검 방법

`npm run lint:feed`는 범주별 최신 회차의 기록을 위 규칙으로 점검합니다. 경고는 게시를 막지 않으며, 게시 계약의 검증은 지금처럼 `npm run validate`가 맡습니다.

~~~sh
npm run lint:feed
node scripts/lint-feed-style.js --all
node scripts/lint-feed-style.js --strict
~~~

`--all`은 범주 파일의 모든 기록을 점검하고, `--strict`는 경고가 하나라도 있으면 실패 코드로 끝납니다.
